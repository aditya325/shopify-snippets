## Roadmap generation — 2026-08-21

Generated by `/pilot:brainstorm` from the v1.1 TDD. Two process notes worth keeping.

**Path deviation.** The brainstorm request named `docs/roadmap/status-log.md`. That path does not exist
and `CLAUDE.md` mandates per-track roadmaps (`docs/roadmap-<track>/`), matching the three existing
tracks. This track was created as `docs/roadmap-pdp/`. A `docs:view:pdp` script was added to
`package.json` per the same convention.

**PRD count was revised down.** The first decomposition proposed 26 PRDs. Calibrating against this
repo's actual output — homepage `phase-2-sections` is 13 PRDs for 13 sections at 89–117 lines each, not
the 40–60 the brainstorm skill suggests — that was 2.6 PRDs per section against a proven 1.0. Revised to
15: strict one-per-section, except `main-product` and `product-details`, which split in two each because
their scope genuinely exceeds anything homepage shipped.

### Process notes

- **`shopify:section:load` is functionally dead here**, as `/assess` observed. The event is editor-only,
  and in the editor `initStickyAtc` returns at the design-mode check before wiring an observer. The
  behaviour is correct; the listener is just not the mechanism a reader might assume.

### Still unverified

✅ **Footer hide confirmed working by the user, 2026-08-24.** The second `IntersectionObserver` and the

✅ **Three more criteria settled by source inspection, 2026-08-24** — two of them conclusively, since
they are properties of the code rather than of a run:

- **Not scroll-offset based.** `assets/sticky-atc.js` contains no `scrollY`, `pageYOffset`, `scrollTop`,
  `getBoundingClientRect`, `innerHeight` or `offsetTop`. Visibility derives solely from
  `entry.isIntersecting` at lines 57 and 66. The implementation **cannot** be viewport-height-sensitive,
  which is what the 500px/1400px criterion exists to prove — a structural proof, stronger than two
  sampled heights.
- **Both directions animate.** `transform 300ms ease-out` is present on the base rule *and* on
  `[data-sticky-visible="true"]`, so entry and exit are both transitioned.
- **`prefers-reduced-motion` switches to instant.** The media block lists **both** selectors, matching the
  visible-state rule's specificity and coming later in source order, so `transition: none` wins in both
  states — including the `visibility` delay.
