# PRD: 2.1 — Product Template Assembly

**Phase:** Phase 2 — Assembly & QA
**Priority:** P0
**Depends on:** All of Phase 1 (1.1–1.6, 1.10–1.12)
**Estimated scope:** Small (1 template JSON, possible section-order corrections)

## Context

By this point the nine sections this sprint builds exist as independent files, each verified against
its own Figma frame in isolation. Two further sections are **reused unchanged** from the homepage
sprint — `sections/see-it-in-action.liquid` (Quinn) and `sections/reviews.liquid` (Judge.me), both
currently `h-[50vh]` placeholder bands. This PRD places them; it does **not** modify them.

`templates/product.json` still carries the themex arrangement it started with: a `"main"` section of type `product` plus a `product-recommendations` section with heading "You
may also like". 1.1 rewrote `sections/product.liquid` in place and 1.2 restored its full block order,
but the template has never held the complete PDP section list in the design's order, and no PRD so far
has rendered two adjacent PDP sections together.

## Goal

`templates/product.json` composing all nine sections in the design's order, with the inter-section
vertical rhythm resolved as a whole rather than section by section, and the superseded
`product-recommendations` section removed.

## Requirements

### Functional
- Section order per TDD §2.1, which is authoritative for both breakpoints — **nine** sections, since
  `external-ratings` is out of scope by decision:
  main-product (gallery + buy box), product-details, frequently-bought-together, trust-strip,
  see-it-in-action, reviews, picked-just-for-you, certified, sticky-atc.
- `see-it-in-action` and `reviews` are added to the template **as they are**. No edit to either file,
  no `@app` slot, no heading setting, no Quinn or Judge.me wiring. Both will render as the existing
  50vh green placeholder bands, which is the accepted outcome for this sprint.
- Because neither file is touched, the homepage's use of both is unaffected by construction.
- Remove the themex `product-recommendations` section, superseded by 1.10 picked-just-for-you.
- Sections are ordered **in the template**, not hard-wired in Liquid, so the merchant can reorder.
- `sticky-atc` renders conditionally and is not part of the visual flow order.
- Resolve the page's inter-section vertical rhythm as one decision. Adjacent margins **collapse to the
  larger of the two and do not sum**, so each section's own margin setting acts as a floor rather than a
  value. Walk every boundary in the rendered page and record the resulting gap against the Figma
  section positions.
- The two reused placeholders carry the homepage's `my-6 lg:my-8` margins and a fixed 50vh height, so
  their boundaries will not match the Figma positions. Record the delta rather than "fixing" it — these
  two sections are out of scope for modification.
- Populate the fixture product from 0.1 into the template's default state so the theme editor and a
  fresh install both render a complete page.

### Non-Functional
- Every section must render without JS errors on a single page load with all nine present — no duplicate
  `data-*` hooks, no two scripts binding the same selector.
- Only one Embla-consuming section may claim a given carousel root; verify `product-gallery.js` and
  `picked-just-for-you.js` do not collide.
- No horizontal page scroll at any width from 320px to 1920px.

## Approach

Edit `templates/product.json` only — this PRD writes no Liquid and no CSS unless the rhythm audit finds
a defect, in which case fix it in the owning section and record it. Build the section list in TDD §2.1
order, then walk the assembled page at both breakpoints against the Figma section y-positions. Margin
collapse is the expected source of discrepancy: a section with 24px top margin below one with 32px
bottom margin yields 32px, not 56px, and this is already live between `hero-text` and `claims` on the
homepage. Where a measured boundary is wrong, the fix belongs in whichever section owns that edge, not
in a wrapper added here. Do not write `config/settings_data.json` while `shopify theme dev` is running —
it overwrites settings the local file lacks. For the fixture, reference the product handle 0.1 recorded
in the status log rather than picking a product.

## Expected Output

- `templates/product.json` — nine sections in design order, `product-recommendations` removed
- Corrections to individual section margins where the rhythm audit finds a defect, in the owning files
- A boundary-by-boundary rhythm table recorded in `docs/roadmap-pdp/status-log.md`

## Dependencies

### Upstream (must be done first)
- 1.1–1.6 and 1.10–1.12 — every section this sprint builds must exist before the page can be composed

### Downstream (unblocked by this phase)
- 2.2 design-qa — needs the assembled page

## Constraints

- Adjacent margins collapse; they do not sum. Decide the page rhythm as a whole here, not per section.
- Do **not** edit `see-it-in-action.liquid` or `reviews.liquid`. They are shared with the homepage and
  are explicitly reused as-is this sprint.
- Do not add wrapper elements to fix spacing. Fix the owning section.
- `product-recommendations` removal must not break any other template that references it — check first.
- Never write `settings_data.json` while the dev server is running.
- Comments are one line or none.

## Acceptance Criteria

- [ ] All nine sections render on `templates/product.json` in TDD §2.1 order at both breakpoints
- [ ] `sections/see-it-in-action.liquid` and `sections/reviews.liquid` are **byte-identical to HEAD** —
      placed, not modified — confirmed by `git diff`
- [ ] `product-recommendations` is removed and no other template broke as a result
- [ ] Reordering two sections in the template reorders the rendered page with no code change
- [ ] A boundary-by-boundary table of measured inter-section gaps versus the Figma positions is recorded
      in the status log, with every discrepancy either fixed or explained
- [ ] The assembled page loads with **zero** JS console errors and zero warnings at both breakpoints
- [ ] No two sections bind the same `data-*` hook — verified by grep across the section and asset files
- [ ] No horizontal page scroll at 320, 375, 390, 768, 1024, 1440 and 1920px
- [ ] The fixture product from 0.1 renders a complete page with no empty sections and no
      `placeholder_svg_tag` output
- [ ] A product with **all** PDP metafields empty renders without error, showing only the sections whose
      content is section-settings-driven
- [ ] `theme check` passes with no new offenses against the pre-sprint baseline
