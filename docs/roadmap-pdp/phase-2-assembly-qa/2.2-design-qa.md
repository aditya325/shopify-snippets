# PRD: 2.2 — Design QA & Sprint Gate

**Phase:** Phase 2 — Assembly & QA
**Priority:** P0
**Depends on:** 2.1 (Product Template Assembly)
**Estimated scope:** Medium (no feature code; corrections across section files, plus the sprint gate)

## Context

After 2.1 (`docs/roadmap-pdp/phase-2-assembly-qa/2.1-product-template-assembly.md`) the page is
composed and its vertical rhythm resolved. Each built section has been verified against its own Figma frame
in isolation, but nothing has yet checked the page for the class of defect that only appears across
sections: token drift, type-scale inconsistency, main-thread contention from nine sections' scripts, and
regressions on non-product templates caused by the two shared-file edits this sprint made
(`snippets/product-card.liquid` in 1.5, and the in-place rewrite of `sections/product.liquid` in 1.1).

This mirrors homepage `docs/roadmap-homepage/phase-5-assembly-qa/5.3-design-qa.md` and is this sprint's
release gate. Note the homepage record: 33 of 33 tracker rows closed as `Done with deviations`, never plain
`Done`, and PRD measurements were wrong three times running — so this pass should expect to find things.

## Goal

A verified, shippable PDP: every section matched to its Figma frame at both breakpoints, no
cross-section inconsistency, no regression on other templates, and every open item collected in one place.

## Requirements

### Functional
- Run `/compare` for the **seven built** sections at both breakpoints against
  `.buildspace/artifacts/pdp/screenshots/`. Record each as match or deviation with a measured delta.
- Do **not** compare `see-it-in-action` or `reviews` — they are reused homepage placeholders and will
  not match their PDP frames by design. Record that gap once, as a known deviation, and move on.
- Audit the five font families the design uses (DM Sans 518 text nodes, Inter 52, Space Grotesk 24,
  Poppins 16, ES Rebond Grotesque 4) against the theme's two variables `--font-primary--family` and
  `--font-secondary--family`. Record which family maps to which variable, and flag any that render as a
  browser fallback.
- Audit colour usage against the tokens in `snippets/css-variables.liquid`. The extraction found heavy
  use of `#466e2e`, `#171717`, `#f4c430`, `#737373`, `#facc15` — confirm each resolves through a token
  rather than a hard-coded hex where a token exists.
- Verify the shared `snippets/product-card.liquid` renders correctly on **all** its consumers after the
  1.5 parameter addition.
- Verify non-product templates are unaffected by the in-place rewrite of `sections/product.liquid`.
- Confirm `sections/see-it-in-action.liquid` and `sections/reviews.liquid` are unmodified — `git diff`
  against HEAD must be empty for both. This sprint places them; it does not touch them.
- **Own the Judge.me placeholder seam.** Three surfaces carry hard-coded rating data with no live
  source: `sections/reviews.liquid` (a placeholder band), the `rating` block's `rating_value` /
  `review_count` text settings built in 1.2, and `snippets/product-card.liquid:93-95`
  (`card_rating_is_placeholder`, `4.7`, `132`). Document all three in one place — a `{% doc %}` block or
  a section in `deviations.md` — so whoever wires Judge.me later has a single entry point. This
  ownership moved here when the review-section PRD was cut.
- Verify all twelve TDD §5 acceptance criteria against the assembled page, marking as N/A any that
  depend on `external-ratings`, which is out of scope.
- Collect every deferred item into `docs/roadmap-pdp/deviations.md`: D1 subscriptions, D2 Flits
  wishlist, D3 Judge.me, D4 collection, D5 alt text, plus F2 delivery-estimate risk, F3 mobile PDF, F4
  hover/focus states, F7 tab height.
- Accessibility pass: keyboard operation of gallery, tabs, FAQ accordion, offers scroller and sticky
  bar; focus visibility throughout; the lab-report modal's focus trap and restore.
- Performance pass: ten sections load nine or more separate JS files. Measure main-thread blocking and
  confirm no section's script runs before it is needed.

### Non-Functional
- A criterion is met only when **verified**, not when intended. Unverified criteria are recorded as
  unverified, not as passed.

## Approach

Write no feature code. Work through the audits above, fixing defects in the owning section file and
recording each as a deviation in that section's status-log row. Use `/compare` against the already-saved
Figma screenshots rather than re-exporting — 39 screenshots at 2x are in
`.buildspace/artifacts/pdp/screenshots/`, and the full node trees are in `raw/specs/` if a measurement
needs settling. Measure by pixel scan of the exports rather than reading numbers off frames; this
repo's PRDs have carried wrong measurements three times, so treat any single-source number with
suspicion. For the font audit, the mapping question is genuine and unresolved: the design uses five
families and the theme exposes two, so the outcome is either a documented mapping or a flagged decision
for the client — not a silent addition of three webfonts. Assert properties, not presence: a check that
an element exists has passed twice in this project while a real defect shipped, so verify the computed
value. Close by writing `docs/roadmap-pdp/DEFINITION-OF-DONE.md` results and updating the status log.

## Expected Output

- `docs/roadmap-pdp/deviations.md` — every open D/OD/F item with owner and current state
- `docs/roadmap-pdp/status-log.md` — final per-PRD rows and the sprint verdict
- Corrections in individual section files where the audits found defects
- A font-family mapping decision recorded, or escalated if unresolvable

## Constraints

- Fix defects in the owning section, never with a patch at the template level.
- Do not mark a criterion met without verifying it. Record unverified as unverified.
- Do not add webfonts to resolve the five-family question without a decision — flag it.
- `theme check` misses schema defaults and metafield existence; a clean lint run is not evidence.
- Never write `settings_data.json` while `shopify theme dev` is running.
- Rebuild Tailwind with `npm run build`, never `build:prod`, and kill watchers first.
