## Context

After 0.1 (`docs/roadmap-pdp/phase-0-foundation/0.1-pdp-data-model.md`) the `product_description`,
`how_to_use`, `how_to_use_step`, `ingredient` and `faq` metaobjects exist with the `pro_tip` text
field, and the fixture product is populated. Two reusable pieces matter: `snippets/accordion.liquid`
already renders a trigger/panel pair with `plus-minus` or `chevron` icons, and `assets/accordion.js`
already implements `data-single-open` group exclusivity — which satisfies the TDD's one-open-at-a-time
FAQ rule without new JS. The lab-report modal triggered from the Description panel is 1.4, not here.

## Goal

A `product-details` section rendering a four-tab strip over switchable panels — Description, How to
use, Ingredients, FAQs — each repeating over its metaobject list, with tabs whose backing metafield is
empty omitted entirely.

## Requirements

### Functional
- Section background `#f9f5ee` across all states. Content width 1320 on desktop.
- Tab strip: desktop 1440×73, padding 0/60/0/60 with a 32 gap; mobile padding 0/20/0/20 with a 22 gap
  and horizontal scroll, since the four labels exceed 390.
- Active tab is DM Sans 700 `#171717` with a 2px `#f4c430` underline; inactive is 500 `#737373`.
  Desktop labels are 26/39; mobile 18/27.
- Panels swap in place — no page load, no URL change, no separate routes.
- A tab whose backing metafield is empty is **not rendered at all** — no label, no empty panel.
- Description panel: body copy from the **native** `product.description` (the `product_description`
  metaobject carries no description field of its own). Includes the 1320×198 intro card on `#fbedb7`
  radius 20, the full-width 1320×500 radius-20 media, the "purity and trust" eyebrow, and the four
  1320×140 benefit cards (`#f9f5ee` fill, `#f4c430` 0.5 border, 46×46 `#f4c430` radius-12 icon).
- Description panel also holds the Action Buttons Row (1320×57) — present in **this panel only**. Its
  two controls are "Product Trust Report" (solid `#466e2e`) and "Detailed Ingredients List" (outlined).
  Wiring the first to the modal is 1.4; render both here.
- How to use panel: Steps Row 1320×400 repeating over `how_to_use.steps`, plus a Pro-Tip Banner
  1320×60 reading the product's `pro_tip` text field.
- Ingredients panel: repeats over the `ingredients` list. The design uses Figma's **GRID** layout —
  1 row × 4 columns on desktop (1320×411), 2 × 2 on mobile (350×546). Cards are image over
  `ingredient-name` (DM Sans 600 20/30 desktop, 16/24 mobile) over `ingredient-benefit` (400 16/24 / 14/20).
- FAQs panel: repeats over the `faqs` list as an accordion, one item open at a time.
- Tab labels are section settings with defaults: `label_description` "Description",
  `label_how_to_use` "How to use", `label_ingredients` "Ingredients", `label_faqs` "FAQs". Note the
  design spells it "Ingrediants" — a confirmed designer typo (F6), built as "Ingredients".
- Visibility checkboxes `show_description`, `show_how_to_use`, `show_ingredients`, `show_faqs`, plus an
  optional `heading` richtext above the strip.
- Panel height transition: the Description panel is 2117 tall against 556, 487 and 420 for the others,
  so the container's height changes on every switch. Animate the height rather than snapping,
  matching the approach agreed for the navigation panels (F7).

### Non-Functional
- Tabs are a real tablist — `role="tablist"`/`role="tab"`/`role="tabpanel"`, `aria-selected`, and
  arrow-key navigation between tabs.
- Only the active panel is exposed to assistive tech; inactive panels are `hidden`, not just visually
  offscreen.
- Panel images lazy-load — this section is below the fold.

## Approach

Create `sections/product-details.liquid`. Build the tab strip and all four panels server-rendered in
one pass, then toggle visibility client-side — this keeps content indexable and avoids a fetch per
tab. Determine tab presence in Liquid before rendering the strip, so the strip and the panel set
cannot disagree: assign a list of enabled tabs from the `show_*` settings **and** a non-blank check on
each backing metafield, then loop it. Extract each panel to its own snippet
(`pdp-panel-description`, `-how-to-use`, `-ingredients`, `-faqs`) to keep the section file readable.
The FAQ panel renders `snippets/accordion.liquid` inside a wrapper carrying `data-single-open` — that
attribute is what `assets/accordion.js:59` looks for, so exclusivity needs no new JavaScript. Write
`assets/product-details.js` as a `DOMContentLoaded` script for tab switching only, driven by `data-*`
attributes. For the height transition, measure the target panel's `scrollHeight` and transition
`max-height` on the panel wrapper, falling back to no animation when
`prefers-reduced-motion: reduce`. The ingredients grid is a Tailwind `grid` with `grid-cols-2
lg:grid-cols-4` — derive card widths from the grid, never declare them.

## Expected Output

- `sections/product-details.liquid` — tab strip, 4 panels, 9 settings
- `snippets/pdp-panel-description.liquid` — intro card, media, benefit cards, Action Buttons Row
- `snippets/pdp-panel-how-to-use.liquid` — steps plus pro-tip banner
- `snippets/pdp-panel-ingredients.liquid` — responsive grid
- `snippets/pdp-panel-faqs.liquid` — accordion list
- `assets/product-details.js` — tab switching and height transition

## Constraints

- The Badges Grid (1320×200) inside the Description panel is `visible: false` in Figma and is excluded.
- The FAQ panel in Figma contains four placeholder rows reading only "Headline text" plus a stray node
  named "Slot" — confirmed scaffolding (F5), excluded.
- Do **not** write a new accordion. `assets/accordion.js` already handles `data-single-open`; adding a
  second implementation would give the page two competing handlers on the same `[data-accordion]` hook.
- Row counts follow metaobject entry counts. No fixed count for steps, ingredients or questions.
- Ingredients uses Figma GRID layout, not row/column auto-layout — read
  `raw/specs/product-details-ingredients-*.txt` rather than assuming flex.
- Vertical spacing is margin on the wrapper; this section paints `#f9f5ee`, so it also takes padding
  for the painted interior.
- Comments are one line or none.

## Acceptance Criteria

- [ ] Four tabs render on the fixture product; clicking each swaps the panel with no page load and no
      URL change
- [ ] Clearing the `ingredients` metafield removes both the Ingredients panel **and** its tab label —
      verified on a second product, not only by toggling the `show_*` setting
- [ ] Setting `show_faqs` false removes that tab and panel while the other three still render
- [ ] Adding a 5th ingredient and a 4th how-to-use step renders both with no code change
- [ ] Only one FAQ answer is open at a time — opening a second closes the first, driven by the existing
      `assets/accordion.js` with no new accordion JS added
- [ ] The Action Buttons Row renders in the Description panel only, and is absent from the other three
- [ ] Tab label settings change the rendered labels; the default reads "Ingredients", not "Ingrediants"
- [ ] Switching between Description and FAQs animates the container height rather than snapping, and
      snaps instead under `prefers-reduced-motion: reduce`
- [ ] Tabs are reachable and operable by keyboard with arrow keys, and inactive panels are not
      reachable by tab order
- [ ] Ingredients renders 4-across at 1024px+ and 2-across below, with card widths derived from the grid
- [ ] `assets/tailwind.css` rebuilt with `npm run build`, unminified; `theme check` shows no new offenses
