## Context

After 1.1 (`docs/roadmap-pdp/phase-1-sections/1.1-main-product-gallery.md`) the rewritten
`sections/product.liquid` renders the shell, the responsive grid and the gallery, with an empty
buy-box column. After 0.1 (`docs/roadmap-pdp/phase-0-foundation/0.1-pdp-data-model.md`) the
`helps_with`, `offers` and `free_gift` metaobjects and metafields exist on the fixture product.
Reusable pieces already in the theme: `snippets/variant-selector.liquid`,
`snippets/product-form.liquid`, `snippets/add-to-cart-button.liquid` (which already accepts
`show_price`), `assets/product-form.js` and the AJAX cart drawer.

## Goal

A complete, merchant-reorderable buy box — ten block types rendering title through free-gift strip —
with working variant switching, AJAX add-to-cart, Buy Now, a pincode delivery estimate, and a
horizontally-snapping offers scroller.

## Requirements

### Functional
- Ten block types per TDD §4.1: `title`, `rating`, `price`, `variant_picker`, `purchase_options`,
  `helps_with`, `offers`, `delivery`, `buy_buttons`, `free_gift`. Order is set by `block_order`.
- Root container: desktop padding 0/60/24/32 with a 32 gap; mobile 24/20/40/20 with a 32 gap.
- `title` — badge, category label, product title (DM Sans 600 36/44 desktop), variant/size label. All
  content read from the product and its metafields; **no** block settings.
- `rating` — `rating_value` and `review_count` as text settings, hard-coded per D3 (Judge.me unwired).
  Design shows 4.7, five `#facc15` stars, and "132 Reviews".
- `price` — sale price (DM Sans 700 32/38), compare-at struck at `#1a1a1a` 0.6 alpha, discount badge
  `#d93807`, and "Inclusive of all taxes". Saving is **derived** from price vs compare-at, never entered.
- `variant_picker` — renders the product's option values as the 80×60 radius-12 size tiles showing
  option name and per-variant price. Active tile is `#466e2e` at 0.1 with a `#466e2e` 0.5 border.
- `purchase_options` — one-time vs Subscribe & save. Per decision it is **selectable but inert**: the
  radio can be chosen and shows the notice "Subscriptions launching soon — this order will be
  one-time". It must set **no** selling plan, no cart property and no line-item property. Do not reuse
  `snippets/selling-plan-selector.liquid` — it `break`s when `selling_plan_groups.size == 0`, which is
  every product today.
- `helps_with` — icon-and-label row from the `helps_with` metaobject list. 80×80 radius-6 images.
  Settings: `metafield_key` (default `helps_with`), `heading`.
- `offers` — "Available Offers" card row inside a `#466e2e` 0.1 radius-20 container. Horizontal
  overflow scroll with scroll-snap so each 352×118 card lands aligned. **No arrows** — none are drawn.
  Each card carries a headline, subtitle, code label and a COPY button that copies the code.
  Settings: `metafield_key` (default `offers`), `heading`.
- `delivery` — pincode input, digits only, capped at 6 characters, with a Check button. On submit the
  block switches to the checked state: "Delivering to {pincode}", "Estimated Delivery by {min} - {max}"
  and a Change Pincode control returning to the input. Settings: `heading`, `subtext`.
- Delivery window is rendered in Liquid as today+`delivery_min_days` to today+`delivery_max_days`,
  formatted short-month-and-day to match the design's "Aug 2 - Aug 5". Both are section settings
  (defaults 3 and 5) so the window changes without a deploy.
- `buy_buttons` — quantity stepper (160×50) plus Add to Cart (AJAX, opens the existing cart drawer)
  and, behind `show_buy_now`, a Buy Now that submits straight to checkout bypassing the drawer.
- `free_gift` — 628×57 radius-12 strip on a radial gradient `#f4c430`→`#72832f`→`#466e2e`, reading the
  `free_gift` metaobject plus the `free_gift_message` section setting.
- Section settings added here: `delivery_min_days`, `delivery_max_days`, `free_gift_message`.
- Variant change updates the URL variant parameter, the price, the compare-at price and the variant
  Add to Cart submits. It does **not** change the gallery — the option is size, not appearance.

### Non-Functional
- Pincode input uses `inputmode="numeric"` and rejects non-digits on input, not only on submit.
- The inert subscription option is announced to assistive tech — the notice is not visual-only.
- Blocks render nothing rather than an empty shell when their backing metafield is blank.

## Approach

Add the ten block types to the rewritten `sections/product.liquid` and render each through
`{% render %}`, extracting any block whose markup exceeds ~30 lines into its own snippet — `offers`
and `delivery` are the likely candidates. Wire variant switching through the existing
`snippets/variant-selector.liquid` and `assets/product-form.js`, which already communicate over a
`variant:change` PubSub event; extend rather than replace that channel. Add to Cart reuses
`snippets/add-to-cart-button.liquid` and the existing drawer — do not change drawer behaviour. Buy Now
posts to `/cart/add` with `return_to=/checkout`. The offers scroller is pure CSS
(`overflow-x-auto` + `snap-x snap-mandatory` + `snap-start` on cards) — no Embla, no JS, since no
arrows are drawn. Pincode is a small `DOMContentLoaded` script in `assets/product-buy-box.js` that
swaps two pre-rendered states rather than building DOM, per the JS standards. Compute the delivery
window in Liquid, not JS, so it is correct with JS disabled and needs no hydration. The COPY button
uses `navigator.clipboard` with a `document.execCommand` fallback and confirms visually. Derive the
size-tile widths from the layout — the 80×60 in Figma is computed, not declared.

## Constraints

- D1 is unresolved: GoKwik/Razorpay is not an eligible gateway for Shopify native subscriptions and
  Recurpay excludes India. `purchase_options` must create no subscription state of any kind.
- D2: Flits is not integrated, so wishlist stays the placeholder 1.1 rendered.
- D3: the `rating` block's values are hard-coded settings, not live data.
- F2: the delivery estimate is display-only and can disagree with checkout. It is not a serviceability
  check — do not imply otherwise in the copy.
- The design does not specify hover/focus states for the offers cards (F4) — follow Global Standards.
- Layout widths derived, not declared. Vertical spacing is margin. Comments are one line or none.

- [ ] COPY places the offer code on the clipboard and confirms visually
