## Context

After 1.2 (`docs/roadmap-pdp/phase-1-sections/1.2-main-product-buy-box.md`) the primary Add to Cart
button exists inside `sections/product.liquid` — this section observes it.

The design carries this bar in two places that disagree, which was TDD OD3. **The decision is closed in
favour of the dedicated frames: 87 tall on desktop, 63 on mobile.** Independent verification supports
it — the `Sticky Add to Cart (NEW)` copies in the base page frames are `visible: false` in **all 15
frames** in the Figma file, while the `Sticky ATC` layers in the two dedicated frames are visible. The
64-tall copies are stale placeholders and are not the build target.

## Goal

A `sticky-atc` section rendering a bottom-anchored purchase bar that appears only once the primary Add
to Cart has scrolled out of view, hides again when the footer appears, and animates in both directions.

## Requirements

### Functional
- Desktop 1440×87, padding 18 vertical and 60 horizontal. Mobile 390×63, padding 12 vertical and 16
  horizontal with a 12 gap.
- Both breakpoints: `#ffffff` fill with a drop shadow of `0 -2px 12px` at `#000000` 12% alpha — the
  upward shadow is what separates the bar from page content and is measured, not decorative licence.
- Desktop contents: product title, price, compare-at price, a quantity stepper, Add to Cart.
- Mobile contents: product title, price, compare-at price, Add to Cart. **No quantity stepper** —
  confirmed intentional in the design.
- Absent on page load.
- Appears only while the primary Add to Cart button in `sections/product.liquid` is out of the viewport.
- Hides again whenever the footer enters the viewport, so it never overlaps footer content.
- Both directions animate — nothing appears or disappears instantly.
- Implemented with `IntersectionObserver` on the primary button **and** on the footer, not on scroll
  position, so behaviour is correct at any viewport height.
- Add to Cart submits the currently selected variant and opens the existing cart drawer, matching 1.2.
- Price and compare-at update on variant change, using the same `variant:change` channel 1.2 wires.

### Non-Functional
- The bar is `aria-hidden` while visually hidden, so it is not reachable by keyboard or screen reader
  when off-screen.
- No layout shift on appearance — the bar is fixed-position and does not reflow page content.
- Animation respects `prefers-reduced-motion: reduce` by switching to an instant state change.

## Approach

Create `sections/sticky-atc.liquid` and `assets/sticky-atc.js`. The bar is `position: fixed` at the
viewport bottom, so it needs no participation in the page's vertical rhythm — but it does paint a
background, so it takes padding for its interior. Render it once from the product template and keep its
markup server-rendered; the JS toggles a class only, and creates no DOM, per the JS standards. Use two
`IntersectionObserver` instances: one on the primary Add to Cart button (`data-*` hook added in 1.2)
and one on the footer element. Combine their states — visible when the button is out of view **and** the
footer is not in view — rather than letting the second observer fight the first. Animate with a CSS
`transform: translateY` transition rather than `height` or `display`, so it composites and cannot cause
layout shift. Reuse `snippets/add-to-cart-button.liquid` and, for the stepper, whatever markup 1.2
produced for the buy box, so the two Add to Cart paths cannot diverge. Subscribe to the same
`variant:change` event 1.2 publishes so price updates need no second source of truth.

## Expected Output

- `sections/sticky-atc.liquid` — fixed bar, desktop and mobile variants
- `assets/sticky-atc.js` — dual `IntersectionObserver` visibility logic
- `sections/product.liquid` — `data-*` hook on the primary Add to Cart button, if 1.2 did not add one

## Dependencies

### Upstream (must be done first)
- 1.2 — the primary Add to Cart button, the quantity stepper markup and the `variant:change` channel

### Downstream (unblocked by this phase)
- 2.1 product-template-assembly — places this section in `templates/product.json`

## Constraints

- **OD3 is closed: 87 desktop, 63 mobile.** The 64-tall copies in the base frames are hidden in all 15
  frames and are not authoritative. A 23px difference on desktop is visible, so do not build to 64.
- Mobile deliberately has no quantity stepper. Do not add one for symmetry.
- Visibility is driven by `IntersectionObserver`, not scroll offset — a scroll-position implementation
  breaks at unusual viewport heights and is explicitly rejected.
- Do not build a second add-to-cart code path. Reuse what 1.2 produced.
- The bar must never overlap the footer.
- Comments are one line or none. JS uses `data-*` attributes and creates no DOM.

## Acceptance Criteria

- [ ] Desktop bar renders 1440×87 with 18 vertical and 60 horizontal padding; mobile renders 390×63
      with 12 vertical and 16 horizontal padding
- [ ] Desktop shows a quantity stepper; mobile shows none
- [ ] The bar is absent on page load at both breakpoints
- [ ] It appears only after the primary Add to Cart has scrolled out of view — verified by scrolling,
      not by toggling a class in devtools
- [ ] It hides when the footer enters the viewport and does not overlap footer content at any scroll position
- [ ] Both appearance and disappearance animate, and switch to instant under `prefers-reduced-motion: reduce`
- [ ] Behaviour is correct at a 500px-tall viewport and at a 1400px-tall viewport, proving the
      implementation is not scroll-offset based
- [ ] Add to Cart from the bar adds the currently selected variant and opens the existing cart drawer
- [ ] Changing the size option updates the bar's price and compare-at price
- [ ] The bar is `aria-hidden` and not keyboard-reachable while hidden
- [ ] No cumulative layout shift is introduced when the bar appears — verified in the performance panel
- [ ] `assets/tailwind.css` rebuilt with `npm run build`, unminified; `theme check` shows no new offenses
