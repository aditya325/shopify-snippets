## Context

After 1.3 (`docs/roadmap-pdp/phase-1-sections/1.3-product-details-tabs.md`) the Description panel
renders the Action Buttons Row with a "Product Trust Report" control that is present but not yet
wired. After 0.1 the `custom.lab_report` file-reference metafield exists on the product. The theme
already has two overlay precedents to follow rather than reinvent: `snippets/drawer-panel.liquid` and
`snippets/search-modal.liquid`.

## Goal

Clicking "Product Trust Report" opens the product's lab report PDF in a modal over the page — without
navigating, without changing the URL — with a reliable fallback on mobile browsers that refuse to
render an embedded PDF.

## Requirements

### Functional
- The modal opens over a scrim, centred, at 620×660 on desktop and 370×510 on mobile, with a 34×34
  close control.
- The URL does not change and the page does not navigate. Browser back does not close the modal by
  navigating away.
- The modal embeds the PDF held in `product.metafields.custom.lab_report`. The report layout drawn in
  Figma is a placeholder for the PDF's own contents and is **not** built as markup.
- Closes on the close control, on scrim click, and on `Escape`.
- Body scroll is locked while open and restored on close, including scroll position.
- If `custom.lab_report` is blank, the "Product Trust Report" control does not render at all.
- Mobile fallback (F3): inline PDF rendering in an embedded frame is unreliable on mobile browsers,
  particularly iOS Safari, which frequently refuses to display it. On small screens present the report
  as an explicit open-in-new-tab / download action rather than an embed. Wording: **"Open Trust Report
  (PDF)"** with a secondary line **"Opens in a new tab"**.
- The fallback is chosen by capability, not by user-agent sniffing.

### Non-Functional
- Focus moves into the modal on open, is trapped while open, and returns to the triggering control on
  close.
- The modal is `role="dialog"` with `aria-modal="true"` and is labelled by its heading.
- The PDF is not fetched until the modal is opened — no embed in the initial page payload.

## Approach

Create `snippets/pdp-lab-report-modal.liquid` and render it once from
`sections/product-details.liquid`, guarded on `custom.lab_report` being non-blank. Read
`snippets/search-modal.liquid` first and follow its scrim, close and focus conventions so the PDP does
not introduce a third overlay idiom. Write `assets/pdp-lab-report.js` as a `DOMContentLoaded` script
keyed on `data-*` attributes; it toggles a class on the modal root and sets the `<iframe>`/`<object>`
`src` on first open so the PDF is lazy. Decide embed-versus-link by capability rather than user agent —
gate on a viewport media query for the layout and treat the embed as best-effort: render the embed with
the open-in-new-tab action always visible beneath it, so a browser that silently fails to paint the PDF
still leaves the user a working route. That single arrangement satisfies both breakpoints and removes
the need to detect iOS at all. Reuse the existing body-scroll-lock approach from the cart drawer or
search modal rather than writing a third one. Focus trap: query focusable descendants on open and
cycle on `Tab`, the same pattern `assets/accordion.js:108` already uses to collect focusables.

## Expected Output

- `snippets/pdp-lab-report-modal.liquid` — dialog markup, scrim, close control, embed plus fallback action
- `assets/pdp-lab-report.js` — open/close, lazy `src`, focus trap, scroll lock
- `sections/product-details.liquid` — Action Buttons Row control wired to the modal

### Downstream (unblocked by this phase)

## Constraints

- F3 is a real risk, not a hypothetical: iOS Safari frequently refuses to render a PDF in an embedded
  frame. Do not ship an embed-only path on mobile.
- Do not introduce a new overlay pattern. Two already exist (`drawer-panel`, `search-modal`); match one.
- The Figma report layout is a placeholder for PDF contents — building it as markup would be wrong work.
- Comments are one line or none. JS uses `data-*` attributes, never class-name selectors, and creates
  no DOM.

## Acceptance Criteria

- [ ] Clicking "Product Trust Report" opens the modal; the URL is unchanged and the page does not navigate
- [ ] Modal measures 620×660 at desktop widths and 370×510 at mobile widths, with a 34×34 close control
- [ ] Closes on the close control, on scrim click, and on `Escape`
- [ ] Focus enters the modal on open, cannot leave it by `Tab` while open, and returns to the
      "Product Trust Report" control on close
- [ ] Body scroll is locked while open and the previous scroll position is restored on close
- [ ] The PDF is not requested until the modal is first opened — verified in the network panel
- [ ] An open-in-new-tab action is present and functional **alongside** the embed, so the report is
      reachable even when the embed does not paint — verified on a real iOS Safari session, not a
      desktop emulation
- [ ] A product with `custom.lab_report` blank renders no "Product Trust Report" control and no modal
      markup at all
- [ ] `assets/tailwind.css` rebuilt with `npm run build`, unminified; `theme check` shows no new offenses
