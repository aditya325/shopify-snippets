## Context

After 1.5 (`docs/roadmap-pdp/phase-1-sections/1.5-frequently-bought-together.md`) the shared
`snippets/product-card.liquid` has its new price-in-button parameter and all ten existing consumers are
verified unchanged. This section renders the same card in a carousel. Embla is vendored and loaded
globally deferred from `snippets/core-assets.liquid:18`; there is **no** shared initialiser module, so
this section writes its own JS, matching the seven existing carousel scripts
(`announcement-bar`, `featured-blogs`, `hero-banner`, `featured-discounts`, `featured-products`,
`media-carousel`, `shop-by-lifestyle`).

## Goal

A `picked-just-for-you` section rendering a product carousel from a merchant-selected **product list**,
using the existing product card and the established per-section Embla pattern.

## Requirements

### Functional
- Desktop 1440×559, padding 0/60/0/60 with a 10 gap — **no vertical padding**. Mobile 390×432, padding
  **24 top only** with a 10 gap — no side padding, so the card rail bleeds to both edges.
- Both breakpoints paint `#ffffff`.
- Settings: `heading` (`richtext`), `products` (`product_list`). **No `collection` setting and no
  `product_count`** — the list is explicit, so there is nothing to cap.
- Products come from the merchant-selected **product list**, **not** a collection and **not** the Shopify
  recommendations endpoint — this keeps output predictable and avoids an empty rail on a low-traffic
  catalogue.
- 🔴 **Decide the scope of the rail before building.** A plain
  `product_list` **section** setting is per-template, so **every product shows the same rail**. That is
  correct only if the rail is genuinely store-wide. "Picked Just For You" implies otherwise, and one global
  list cannot vary by product.
  **The setting supports both, with no code change:** a `product_list` setting accepts a **dynamic source**
  from a `list.product_reference` product metafield. Leave it plain for one store-wide rail; bind it per
  product for a product-specific one — **exactly the mechanism 1.5 now uses** for
  `custom.bought_together`.
  ⚠️ This is the error 1.5 shipped and had to correct — see `status-log.md`, "1.5 — data source corrected".
  A per-product rail needs its own `list.product_reference` metafield created (do **not** reuse
  `bought_together`, which means something else), which makes this depend on 0.1.
  ⚠️ If a binding is used the template stores
  `"{{ product.metafields.custom.<key>.value }}"` — the **`.value` suffix is load-bearing**; omitting it
  returns **HTTP 500**. The format is undocumented and cannot be hand-authored reliably; connect it in the
  theme editor, which writes the correct string.
- **No maximum is imposed on the list**, matching 1.5. Decide from the desktop spec what happens past the
  drawn card count — 1.5 switches to an Embla rail with a fractional slide once the static row would start
  shrinking cards below their drawn width.
- Cards are `snippets/product-card.liquid`. Price-in-button is **not** used here — that treatment is
  specific to FBT — so leave the new parameter at its default false.
- Carousel: mobile is a swipeable Embla rail; on desktop, follow whatever the measured card count and
  frame width imply — read the desktop spec before deciding whether it scrolls or lays out statically.

### Non-Functional
- Card images lazy-load; this section is well below the fold.
- The carousel is keyboard operable and communicates active state, matching `assets/media-carousel.js`.
- Guard on `window.EmblaCarousel` and return early if absent, so a failed script load degrades to a
  scrollable row rather than a broken section.

## Approach

Create `sections/picked-just-for-you.liquid` and `assets/picked-just-for-you.js`. The section paints
`#ffffff`, so it carries both margin on the outer wrapper for separation and padding on the painted
element for its interior — but the measured desktop vertical padding is 0, so only the 60 side padding
applies there. Card widths derive from the layout: `flex-1` on desktop
where the row divides the content width, and `basis-[calc(100%/N)]` on mobile for the measured slide
ratio — read the mobile spec for the actual visible-card count rather than assuming, since this repo's
PRDs have had gap and ratio values wrong three times running. Write the JS as a `DOMContentLoaded`
script reading `data-*` attributes, copying the shape of `assets/shop-by-lifestyle.js`, which is the
closest analogue (mobile carousel, static desktop) and is the project's designated carousel
shape-setter. Iterate the `products` list directly and render nothing when it is empty or unset. D4 — which
products feed this — is unresolved; ship the setting empty, so this is a merchant configuration step and
not a blocker.

## Expected Output

- `sections/picked-just-for-you.liquid` — section, heading, product carousel
- `assets/picked-just-for-you.js` — Embla initialisation and state sync

## Constraints

- D4: the products feeding this are unconfirmed. Ship the setting empty; do not hard-code product handles.
- Do not use the Shopify product-recommendations endpoint, and do not source from a collection — the
  decision is an explicit merchant-selected product list, for predictability.
- No shared Embla initialiser exists. Do not create one here; match the per-section pattern.
- Zero vertical padding on desktop and zero side padding on mobile are both measured and intentional.
  Do not add `py-*` or `px-*` to make it "look right" — the neighbouring sections' margins supply the
  rhythm, and the mobile rail is meant to bleed.
- Layout widths derived, never declared. Verify gap and slide ratio by measuring the Figma export
  rather than reading a number off a frame.
- Comments are one line or none.

### Carried forward from 1.4–1.6 — each of these shipped as a defect and was corrected

Verified against this codebase on 2026-08-24. Do not rediscover them.

- 🔴 **The degradation criterion below cannot be met by copying `shop-by-lifestyle`.**
  `sections/shop-by-lifestyle.liquid:47` puts `overflow-hidden` on the carousel viewport and its JS returns
  early when `window.EmblaCarousel` is absent — so a blocked script leaves the slides **clipped and
  unreachable**, not scrollable. `media-carousel` has the same flaw. Ship
  `overflow-x-auto scrollbar-hide` and have the JS set `data-embla="ready"` on successful init, with
  `data-[embla=ready]:overflow-hidden` handing scrolling over. See `sections/frequently-bought-together.liquid`.
- 🔴 **A section that ships its JS only when it has content cannot initialise on a merchant's first run.**
  This PRD renders nothing when the product list is empty, so no script ships; when the merchant then picks
  products, `DOMContentLoaded` has already fired and the injected script's listener never runs. The
  carousel stays dead until an editor reload — **the default onboarding path**. Init when
  `document.readyState !== 'loading'`, register `shopify:section:load` at top level, and put the
  `window.EmblaCarousel` guard **inside** the per-carousel init so a late-loading library does not disable
  the section permanently.
- 🔴 **Never compare a Liquid-derived count against an embla snap count across breakpoints.** This trap has
  appeared **three times**. Liquid cannot see the viewport, so a dot count computed in Liquid is
  breakpoint-blind, while `scrollSnapList()` is breakpoint-aware — and embla's `active: false` breakpoint
  skips handler wiring, **not** engine construction, so it still reports snaps where it is "inactive". Gate
  any such comparison to the breakpoint where the dots are actually visible.
- 🔴 **`flex-1` honours `min-width: auto`.** A long unbreakable product title sets a min-content floor and
  steals width from its siblings — measured at 320px as `74.05 / 97.84 / 74.05 / 74.05` against a uniform
  spec. Add `min-w-0` to the flex child and `break-words` to the text.
- 🔴 **`lg:basis-auto` silently defeats `lg:flex-1`.** Tailwind emits `.lg\:basis-auto` **after**
  `.lg\:flex-1` at equal specificity, so it reinstates content-based sizing — and it is invisible in the
  class attribute. This survived three review passes.
- ⚠️ **Assert computed values, never class presence.** Three consecutive passes accepted "the class is on the
  element" as proof and shipped a width defect. Read `getBoundingClientRect()` and `getComputedStyle()`.
  For a font weight, also check `document.fonts.check()` — `getComputedStyle` reports the *requested*
  weight and passes on a fallback face.
- ⚠️ **Harness limits.** The automation tab runs `document.hidden === true`, so `requestAnimationFrame` and
  `IntersectionObserver` never fire and pdf.js/embla render loops stall. Mobile cannot reflow below `lg`.
  Measure mobile in a **same-origin iframe built from fetched HTML plus a `<base>` tag** — `src=<url>` goes
  cross-origin because the dev server redirects. Shim `rAF` inside the frame when a render loop must run.
- ⚠️ **Use `?section_id=` renders, with the template *key* not the section *type*.** The type returns an
  empty wrapper from schema defaults. Repeated ~5MB page fetches triggered an **HTTP 429** that blocked
  verification for hours during 1.5.
- ⚠️ **Renaming a setting id is a schema/template contract change, not cosmetic.** Doing it against a running
  `theme dev` emptied a working section — the server held the old schema and dropped the unknown setting.
  Restart `theme dev` first.

## Acceptance Criteria

- [ ] Desktop renders 1440×559 with 0/60/0/60 padding and a 10 gap, and **no** vertical padding
- [ ] Mobile renders 390×432 with 24 top padding, **no side padding**, and a 10 gap
- [ ] Both breakpoints paint `#ffffff`
- [ ] Products come from the `products` list setting; changing the list changes the rendered products
- [ ] An empty or unset `products` list renders no section output rather than an empty rail or a lone heading
- [ ] No `collection` setting and no `product_count` setting exist in the schema
- [ ] Cards render without price-in-button — the FBT treatment does not leak here
- [ ] Mobile swipes between cards; the measured slide ratio matches the Figma export by pixel scan, not
      by a number read off a frame
- [ ] With `embla-carousel.umd.js` blocked, the section degrades to a **natively scrollable** row and logs
      no error — verified by removing the ready flag and asserting computed `overflow-x` is `auto` with
      content overflowing, **not** by reading the class list
- [ ] Card images carry `loading="lazy"`
- [ ] The rail's scope is a recorded decision: either a store-wide `product_list` setting, or a per-product
      `list.product_reference` metafield bound by dynamic source. Whichever ships, the other is recorded as
      considered and rejected
- [ ] Adding the section from its preset in the theme editor and *then* choosing products produces a
      working carousel **without** an editor reload
- [ ] Card widths are equal at 320, 390 and 1440 even with the longest product title in the list
- [ ] `assets/tailwind.css` rebuilt with `npm run build`, unminified; `theme check` shows no new offenses
