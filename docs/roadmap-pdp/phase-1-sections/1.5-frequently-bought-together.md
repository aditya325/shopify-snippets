## Context

`snippets/product-card.liquid` is the shared card used by **ten** consumers — 8 sections plus
`snippets/mega-menu-products.liquid` and `snippets/search-modal.liquid` — and was last modified by
homepage 2.4. Verified against the current file, it **already** renders a rating row
(`card_rating_value = 4.7`, `card_rating_count = 132` — hard-coded placeholders that match this
design's values exactly) and **already** computes `card_discount_percent` from compare-at price. It
also already exposes `hide_price`, `hide_add_to_cart`, `show_featured_image`, `lazy_load` and
`card_class`. Separately, `snippets/add-to-cart-button.liquid` **already accepts `show_price`**
("Show price inside button"). This closes most of TDD OD2: the card work is one prop passthrough, not
a rating and discount build.

## Goal

A `frequently-bought-together` section rendering companion products as existing product cards with the
price shown inside the Add to Cart button, each card adding independently.

## Requirements

### Functional
- Desktop 1440×588, padding 52/60/52/60 with a 12 gap. Mobile 390×412, padding 24/20/24/20 with a 12 gap.
- Background `#466E2E` at 20 percent opacity.
- Heading "Complete your pain-relief kit", as `richtext` so a word can be italicised for the existing
  curved-underline utility.
- `products` is a `product_list` section setting **bound to a product metafield by dynamic source** —
  not a plain section setting. Companions vary per product, so the data belongs on
  the product; the section setting is only the reference point the dynamic source attaches to.
  The metafield is `custom.bought_together` (`list.product_reference`), and the template stores the binding
  as `"bought_products": "{{ product.metafields.custom.bought_together.value }}"`.
  ⚠️ The `.value` suffix is load-bearing — omitting it makes the template invalid and the page returns 500.
  ⚠️ The binding format is undocumented and **cannot be hand-authored reliably**; connect it in the theme
  editor via the setting's dynamic-source control, which writes the correct string.
- **Four companions fill the desktop row; more than four turn it into a carousel.** At ≤4 the row is static
  and each card derives the drawn 315px. Above 4, embla initialises on desktop with `4.2` slides visible
  (`calc(100%/4.2)` = 314.28 at 1320, so the card stays on-design and the fraction gives a peek). Mobile is
  a 2-up carousel at any count. **No maximum is imposed** on either the setting or the metafield.
- Cards are `snippets/product-card.liquid`, rendered with the price inside the button to match the
  design string "Add @325 399".
- Add `show_price` (or equivalently named) as a passthrough parameter on `product-card` that forwards
  to `add-to-cart-button`'s existing `show_price`. Default it **false** so the ten existing consumers
  are byte-for-byte unaffected.
- Each card adds its own product independently.
- **No add-all control and no checkboxes.** Verified in Figma: the "Add all 3" text node is
  `visible:false` inside a visible frame inside a hidden frame — hidden at two levels. It is not built.
- Card rating and discount come from the card's existing behaviour — this PRD adds neither.

### Non-Functional
- Card images lazy-load; this section is below the fold.
- Modifying the shared card must not change rendering for its ten existing consumers.

## Approach

Create `sections/frequently-bought-together.liquid`. Vertical spacing is margin on the outer wrapper;
because this section paints a background, the painted element also takes padding for its interior —
both, per the project rule. Express the 20 percent green as an alpha value on `#466E2E`, matching how
the existing `see-it-in-action` placeholder writes `bg-[#466E2E1A]`. Card widths derive from the
layout: a flex row with `gap-3` and `flex-1` on desktop; on mobile, cards are a horizontally scrolling
row using `basis-[calc(100%/N)]` for the measured slide ratio rather than a declared width — read the
mobile spec for the actual visible-card count before choosing N. For `product-card`, add the new
parameter to the `{% doc %}` block, default it via the existing `if x == null` idiom at the top of the
snippet, and forward it in the single `{% render 'add-to-cart-button' %}` call at line 266. That is
the whole card change — resist widening it. Because this snippet is shared by ten consumers, verify the
other consumers render unchanged before considering this done.

## Expected Output

- `sections/frequently-bought-together.liquid` — section, heading, product row
- `snippets/product-card.liquid` — one new documented parameter, defaulted false, forwarded to
  `add-to-cart-button`

## Constraints

- `snippets/product-card.liquid` is shared by **ten** consumers. Homepage 2.4 already modified it once and
  the status log flags that as a cross-cutting risk. Change only what this PRD names.
- Do not build the add-all control. It is hidden at two levels in Figma and excluded by decision.
- Do not build a rating row or discount badge — both already exist in the card.
- An unprefixed `px-*` overrides `.page-width` at every width. Pair both breakpoints.
- Layout widths derived, never declared. Comments are one line or none.
