# PRD: 4.2 — Secondary Result Groups & Empty States

**Phase:** Phase 4 — Typed State
**Priority:** P0
**Depends on:** 4.1 Product Results Grid
**Estimated scope:** Small (1-3 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-38189
- **Mobile:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-39742
- **Frames:** View All only — `Show More Button` (463:38508) desktop, `CTA Default` (463:39783) mobile.
- **No design exists** for the collections, pages or articles groups, or for the no-results state. Those are built to the design system, not extracted.

## Context

After 4.1 (`docs/roadmap-search/phase-4-typed-state/4.1-product-results-grid.md`), typed product results
render as `product-card` grids. `sections/predictive-search.liquid` still carries its original generic
markup for collections, pages and articles — flat link lists with `text-muted` classes that predate this
design system — and its own inline "View all results" link. 1.1 provided `no_results_text`,
`no_results_cta_label` and `no_results_cta_link`. The Figma section contains six frames and none of them
draws a secondary result group, a loading state, or a no-results state.

## Goal

The rest of the typed panel complete — collections, pages and articles as grouped link lists styled
consistently with the design system, the View All control at design fidelity on both breakpoints, and a
no-results state driven by theme settings.

## Requirements

### Functional
- Collections, pages and articles each render as a grouped link list with a group heading, using the same
  20×20-icon-plus-title pattern as `snippets/search-group-heading.liquid`
- Group styling follows the design system — Space Grotesk Medium 20px headings, DM Sans body, the theme's
  border and radius tokens — not the section's inherited `text-muted` treatment
- A group renders only when its resource type returned results
- No caps in Liquid on any group; `resources[limit]` governs (set in 1.2)
- **View All desktop:** `#466e2e`, radius 12, `px-14 py-9`, full width of the results row, label DM Sans Bold 20px/30 tracking −0.4 `capitalize` white, plus an 18×18 arrow pointing right
- **View All mobile:** `#466e2e`, radius 8, `py-10`, label DM Sans SemiBold 14px/21 white, **no arrow**
- View All submits the current query to `routes.search_url` (Sprint §4.5 — that page is unstyled until the PLP sprint; this is expected, not a defect)
- Remove the section's existing inline "View all results" link
- **No results:** renders `no_results_text`, plus a button using `no_results_cta_label` and `no_results_cta_link`
- The no-results state replaces all result groups and hides View All

### Non-Functional
- Every group heading and link is keyboard-reachable with a visible focus indicator
- Secondary-group links carry accessible text; icon-only elements have accessible names

## Approach

Rewrite the collections, pages and articles branches of `sections/predictive-search.liquid` together —
they are three instances of one pattern, so build one grouped-list snippet parameterised by resource type
and heading rather than three near-copies. Since no design exists for these groups, derive their
treatment from what *is* drawn: reuse the heading pattern from 3.1 and the chip/border tokens from the
default state, so the typed panel reads as one system with the rest of the modal. Collections were only
requestable because of the API switch in 1.2 — the `/search` route cannot return them — so this group is
new surface area that F2 asks to be reviewed once built; flag it for review rather than treating it as
signed off. The two View All variants differ enough (radius, weight, size, arrow) that they are one
element with breakpoint utilities, not two blocks. The no-results state is a sibling container to the
results container, toggled by the same machinery 2.2 built.

## Expected Output

- `sections/predictive-search.liquid` — three secondary groups, View All, no-results state
- `snippets/search-result-group.liquid` — shared grouped-link-list primitive
- Three 20×20 icon snippets for the collections, pages and articles headings

## Dependencies

### Upstream (must be done first)
- 4.1 — the product group must be settled before the groups below it are placed
- 1.1 — provides the three no-results settings
- 1.2 — provides the collections resource
- 2.2 — provides the state-transition machinery the no-results state toggles through

### Downstream (unblocked by this phase)
- None — this completes the sprint's build scope

## Constraints

- The secondary groups and the no-results state have **no design reference** (D-16). Their treatment is derived from the design system and must be recorded as a deviation, not presented as extracted
- Collections are undesigned surface area added by decision (D-11); F2's "review once built" applies to all three secondary groups
- `no_results_text` supersedes the `search.no_results_html` locale string, and the TDD's default copy carries no query term (D-23) — do not reintroduce the term unless asked
- The search results page is out of scope (Sprint §1); View All links to it unstyled and that is not a defect
- Do not add a `type=collection` request to the `/search` route anywhere — it is unsupported there

## Acceptance Criteria

- [ ] A query matching products, collections, pages and articles renders four distinct groups, each with a heading
- [ ] Each group is absent — heading included — when its type returned nothing
- [ ] Group headings use Space Grotesk Medium 20px `#171717`, matching the default-state groups
- [ ] `grep -n "text-muted" sections/predictive-search.liquid` returns nothing
- [ ] Desktop View All measures radius 12 with `px-14 py-9`, label 20px Bold, with an 18×18 right-pointing arrow
- [ ] Mobile View All measures radius 8 with `py-10`, label 14px SemiBold, and has **no** arrow
- [ ] View All navigates to `routes.search_url` carrying the current query
- [ ] A query with zero results across all four types shows `no_results_text` and the CTA, with View All hidden
- [ ] Changing `no_results_cta_label` in theme settings changes the button label with no code change
- [ ] With `no_results_cta_link` unset, the CTA does not render as a dead link
- [ ] Clearing the query from the no-results state returns to the default groups
- [ ] All four groups and both empty states pass a keyboard pass with visible focus
- [ ] Desktop View All matches `figma-searched-product-desktop.png`; mobile matches `figma-searched-product-mobile.png`
