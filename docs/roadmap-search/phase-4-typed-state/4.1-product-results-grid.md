# PRD: 4.1 — Product Results Grid

**Phase:** Phase 4 — Typed State
**Priority:** P0
**Depends on:** 1.2 Predictive Search API Switch, 2.1 Modal Shell (Responsive)
**Estimated scope:** Small (1-3 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-38189
- **Mobile:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-39742
- **Frames:** `Searched Product - Desktop` (463:38189) and `Searched Product` (463:39742). Results row `463:38239` desktop, `463:39773`/`463:39778` mobile.

## Context

After 1.2 (`docs/roadmap-search/phase-1-foundation/1.2-predictive-search-api-switch.md`), typed results
come from `/search/suggest` through `sections/predictive-search.liquid`, still carrying that section's
original generic markup — a flat link list with 56px thumbnails and no Add to Cart. 1.2 also recorded
whether predictive-search product objects expose `metafields.custom.*`; **read that result before
planning this PRD**, because `product-card` depends on six of them. After 3.2 the same card grid is
already proven in the default state.

## Goal

Typed product results rendering the shared `product-card` with Add to Cart at design fidelity — four
across on desktop, two columns on mobile — replacing the section's generic list markup.

## Requirements

### Functional
- Products render via `{% render 'product-card' %}` with Add to Cart shown
- Desktop: one row, `flex` with 20px gap, each card `flex-1` — deriving 265px at four cards in 1120
- Mobile: two columns, 10px gap, each column `flex-1` — deriving 170px in 350
- The number rendered is governed by `search_results_count` passed as `resources[limit]` in 1.2 — no cap in Liquid
- Remove the flat link-list product markup and its 56px thumbnail treatment
- Add to Cart uses the existing cart-drawer flow unchanged; the modal stays open behind the drawer (Sprint §4.4)
- Cards lazy-load their images
- The product group does not render when the query returns no products, even if other types matched

### Non-Functional
- Injected results must not shift the panel's height mid-fade — the transition machinery is 2.2's, this PRD must not defeat it

## Approach

Rewrite only the products branch of `sections/predictive-search.liquid`, leaving collections, pages and
articles for 4.2. Iterate `predictive_search.resources.products` and pass each to `product-card`; the
card is metafield-driven and already correct, so this is a render swap, not a card rebuild. Grid geometry
is identical to 3.2 — `flex` plus gap with `flex-1` children — so lift that structure rather than
inventing a second one; at four cards in 1120 with a 20px gap it derives 265px, matching the measured
457px-tall card row. **If 1.2's smoke test found metafields unavailable**, stop and raise it: the fallback
is either syncing the six values into product tags (which predictive search does index) or rendering a
reduced card, and both are scope changes that need a decision before code. Do not silently ship cards
with empty badge and category regions.

## Expected Output

- `sections/predictive-search.liquid` — products branch rendering `product-card`
- No change to `snippets/product-card.liquid`

## Dependencies

### Upstream (must be done first)
- 1.2 — provides the predictive-search response and the metafield verdict that gates this PRD
- 2.1 — provides the typed panel these results render into

### Downstream (unblocked by this phase)
- 4.2 secondary-groups-and-empty-states — needs the product group settled to sit beneath it

## Constraints

- **Hard gate:** if predictive-search product objects do not expose `metafields.custom.*`, `product-card` renders blank badge, category, highlight and card image. Sprint §1's "product-card unchanged" premise fails and this PRD must not proceed on assumption (D-24)
- Predictive search does not index metafields, so a query matching a `highlight_text` or `category_label` value will not return that product. This is a platform limit, not a defect
- No declared card width (CLAUDE.md)
- `product-card` is shared with eight other call sites and must ship unchanged
- `resources[limit]` is platform-capped at 10, so the grid can never exceed 10 products

## Acceptance Criteria

- [ ] 1.2's metafield verdict is read and recorded in this PRD's status row before implementation starts
- [ ] A query matching four or more products renders four cards in one desktop row at exactly 265px each, derived not declared
- [ ] Mobile renders two columns at 170px in 350px with a 10px gap
- [ ] Cards render badge, category eyebrow, highlight line, rating, price and Add to Cart — each asserted present with real content, not merely present as an element
- [ ] Add to Cart from a result opens the cart drawer with the modal still open behind it
- [ ] Two consecutive adds from the same result set both succeed without re-querying
- [ ] A query matching only pages renders no product group and no empty heading
- [ ] Setting `search_results_count` to 2 returns and renders two products
- [ ] `grep -n "h-14 w-14" sections/predictive-search.liquid` returns nothing — the old thumbnail treatment is gone
- [ ] `snippets/product-card.liquid` is byte-identical to before this PRD, and its eight other call sites are unaffected
- [ ] Desktop matches `figma-searched-product-desktop.png`; mobile matches `figma-searched-product-mobile.png`
