# PRD: 3.1 — Chip Groups (Recent Search + Browse by Concern)

**Phase:** Phase 3 — Default State
**Priority:** P0
**Depends on:** 1.1 Search Settings & Code Retirement, 2.1 Modal Shell (Responsive)
**Estimated scope:** Medium (4-7 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-37505
- **Mobile:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=463-39655
- **Frames:** Recent Search group `463:37537` / `463:39688`; Browse by concern group `463:37560` / `463:39705`. Measured values in `.buildspace/artifacts/search/design-context.md`.

## Context

After 2.1, the panel renders empty at design fidelity. After 1.1, `search_recent_heading`, `search_concern_heading`,
`search_concern_menu` and `recent_searches_limit` exist as settings. `assets/search-recent-searches.js` already
stores recent queries under `themex-recent-searches`, renders them through the Section Rendering API via
`sections/recent-searches.liquid`, dedupes case-insensitively, drops substrings, and provides a
`#clear-recent-searches` control — all reused. Its cap is hardcoded at `MAX_RECENT = 5` and must become
merchant-configurable. This PRD also establishes the shared group-heading pattern that 3.2 reuses.

## Goal

Both chip groups rendering at design fidelity on both breakpoints, with the recent-searches cap driven
by a theme setting and the concern chips driven by a navigation menu.

## Requirements

### Functional
- **Shared group heading:** a 20×20 icon plus title, 12px gap; title in Space Grotesk Medium 20px `#171717`. Icons ship as SVG snippets in code, not merchant-uploaded (Sprint §3.1)
- Group stack: 24px gap between groups on both breakpoints
- **Recent Search desktop:** chips in a 6-column grid, 20px gap both axes, height 42, radius 30, `px-10 py-9`, 1px `#d4d4d4` border, label DM Sans Medium 16px `#171717`
- **Recent Search mobile:** 2-column grid, 10px gap both axes, radius 26, `px-10 py-8`, label DM Sans Medium 14px
- Chip widths derive from content — never declare the Figma computed widths (150 desktop; 159 / 148 / 191 mobile)
- `MAX_RECENT` in `assets/search-recent-searches.js` reads `recent_searches_limit` from a `data-*` attribute, falling back to 6 if absent
- Recent Search group is omitted entirely when there is no history (Sprint §4.2)
- Retain the `#clear-recent-searches` control and its `search.clear_history` string (D-21)
- **Browse by concern desktop:** chips from `settings.search_concern_menu.links`, `flex` with 10px gap, each `flex-1`, height 42, radius 20, `p-10`, 1px `#d4d4d4`, label DM Sans Medium 16px
- **Browse by concern mobile:** rows of two, 10px gap between rows and between chips, each `flex-1`, radius 26, `px-10 py-8`, label 14px
- Concern chips capped at 6 rendered items (D-18)
- Hover and focus states on both chip types — undrawn in the design, built to house convention (F4)

### Non-Functional
- Chips are keyboard-reachable with a visible focus indicator
- Clicking a recent chip repopulates the input and re-runs the query, as it does today

## Approach

Render both groups into the default-content container in `snippets/search-modal.liquid`, extracting the
group heading into a shared snippet so 3.2 consumes the same one. Recent Search keeps its existing
Section Rendering path — restyle `sections/recent-searches.liquid`'s markup, do not rewrite the fetch.
Pass the limit as `data-recent-limit` on `#recent-searches-section` and read it in
`assets/search-recent-searches.js`. ⚠️ **Corrected at execution — replacing the module-level `MAX_RECENT`
constant is not sufficient.** That constant is read only when *saving*; the renderer sends every stored
entry, so a returning user with 5 stored entries would still see 5 chips at a limit of 3. The limit must
be applied on **save and render**. Keep the dedupe and
substring logic untouched. Concern chips are a plain `{%- for link in settings.search_concern_menu.links limit:
6 -%}` loop — `link.title` is the label, `link.url` the destination. Both chip types are the same visual
primitive at two radii, so build one chip snippet with the radius passed in rather than two near-copies.
⚠️ **Corrected at execution — this reference does not exist.** The mega-menu rail styles `aria-selected`,
not hover, and the theme had no `focus-visible` convention before 2.2 added one. The real house idiom is
`[@media(hover:hover)]:hover:` from `mega-menu-group.liquid`, paired with 2.2's focus outline. Both states
are undrawn in Figma (D-17/F4) and still need designer sign-off. Original text: follow the
theme focus ring — so the two systems agree.

## Constraints

- Sprint §3.1's `concern_chip` block model is unavailable; chips come from a `link_list` (D-2). The merchant edits them in Content → Menus, not in the customizer
- No layout element declares a width — chip widths derive from content and the grid (CLAUDE.md)
- The existing dedupe removes case-insensitive duplicates and substrings, so the design's repeated chip labels are unreproducible mockup filler, not a spec
- Hover and focus have no design reference; the house convention is a deviation on record (D-17), not an extracted value

## Acceptance Criteria

- [ ] Group gap measures 24px on both breakpoints; heading icon is 20×20 with a 12px gap to the title
- [ ] Recent chips are 42 tall with radius 30 on desktop and radius 26 on mobile — asserted from computed style
- [ ] Recent chip widths vary with label length; no chip carries a declared width
- [ ] Setting `recent_searches_limit` to 3 renders at most 3 recent chips without a code change
- [ ] With `localStorage` cleared, the Recent Search group does not render at all — not an empty heading
- [ ] `#clear-recent-searches` empties the group and the stored key
- [ ] Clicking a recent chip repopulates the input and re-runs the query
- [ ] Concern chips render from `search_concern_menu`; adding a menu item adds a chip with no code change
- [ ] A menu with 9 items renders exactly 6 chips
- [ ] With `search_concern_menu` unset, the group does not render
- [ ] Every chip is keyboard-reachable with a visible focus indicator and a hover state
- [ ] Desktop matches `figma-search-desktop.png` and mobile `figma-search-mobile.png` for both groups
