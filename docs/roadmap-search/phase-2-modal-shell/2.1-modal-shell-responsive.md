## Context

After 1.1, `snippets/search-modal.liquid` holds a pruned shell: a centred `max-w-2xl` panel with
`bg-black/50` backdrop, applied identically at every breakpoint. The design calls for two different
patterns — a desktop overlay panel over a blurred backdrop, and a mobile full-screen takeover below
the site header. The header is `sticky top-0 z-50` with `min-h-[66px]` on mobile and `lg:h-[110px]` on
desktop; the modal is `z-[60]`, so it already sits above the header.

## Goal

The modal shell rendering at design fidelity on both breakpoints — blurred backdrop, external close
control, search bar and panel on desktop; full-screen takeover with an underlined search row on mobile
— with the panel width and height rules holding across the whole viewport range.

## Requirements

### Functional
- Backdrop: `#000000` at 20% with a 6px blur. Reuse the exact utility pair already proven at `sections/header.liquid:32` — `bg-black/20 backdrop-blur-[6px]`
- Desktop close control: 44×44, radius 12, positioned outside the panel at top right, icon 15×15
- Desktop search bar: radius 20, `px-40 py-6`, inner row height 48, background white
- Desktop panel: radius 20, `px-40 py-18`, background white, 10px below the search bar
- Panel width: a percentage below 1280, fixed 1200px from `xl` (1280) up
- Panel height: `max-height` at the measured Figma values — 741 default, 551 typed — with the content scrolling inside, not a fixed height
- Mobile: full-screen takeover starting below the live header, `pt-10 px-18`, inner row height 48, with a `border-b` of `rgba(33,33,33,0.1)` under the row
- Mobile clear control: 24×24, right-aligned in the row, shown only when the input has a value
- Mobile content container: **`p-5` (20px all round) in BOTH states**. ⚠️ **Corrected during execution:** the PRD's `py-18` default is not supported by the exports — two independent hard-edge anchors measure 20px (default 20.5±0.5 via the group-title icon box, typed 20.0 exactly via the card border), and `design-context.md:213` records only the *side* inset. This is what makes the content column 350 wide in a 390 viewport, which every mobile grid in Phases 3 and 4 derives from
- The mobile header offset must be measured at runtime and applied via a CSS custom property — not hardcoded
- Placeholder `Search by product name` at 16px `#737373`; the filled value at 16px `#171717`

### Non-Functional
- No layout shift when the modal opens; the header must not jump
- `prefers-reduced-motion: reduce` disables the open and close transitions

## Approach

Build one responsive markup pass in `snippets/search-modal.liquid` with breakpoint utilities, not two
branches — the two patterns differ in layout but share every element. The width rule is
`w-[percentage] xl:w-[1200px]`; do not declare 1200 below `xl`, where it overflows a 1024 viewport by
176px. Heights are `max-h-*` plus `overflow-y-auto` on the scroll container, replacing the current
`max-h-[60vh]`; the measured 741/551 are ceilings, and the panel is shorter when Recent Search is
absent per Sprint §4.2. For the mobile offset, measure the header's `offsetHeight` on load and on
resize in `assets/search-modal.js`, write it to a `--search-header-offset` custom property, and consume
it with `top-[var(--search-header-offset)]`; the header is `min-h-[66px]`, so it grows with content and
a static 117px from the design would be wrong. Section-specific CSS that is not expressible as a
utility goes in a search-scoped CSS file loaded by the section, per project convention — not
`src/input.css`.

## Expected Output

- `snippets/search-modal.liquid` — full responsive shell markup
- `assets/search-modal.js` — header-offset measurement writing `--search-header-offset`
- ⚠️ **No CSS file was created and `sections/header.liquid` was not touched.** Every value proved expressible as a Tailwind utility, including `top-[var(--search-header-offset)]`. Follows the homepage 1.5 precedent (a 248-line `base.css` block reversed to all-Tailwind, shipping ~1.2 KB smaller)
- `locales/en.default.json` — **not anticipated by this PRD**: `search.placeholder` changed to the design's copy, `search.clear` added

## Constraints

- CLAUDE.md: no static fixed width on a layout element; widths derive from the layout. The 1200 above `xl` is an explicit, approved exception (D-8) — it is a container ceiling, not a card width
- An unprefixed `px-*` overrides `.page-width` at every width; pair both breakpoints on any padding override
- The design's mobile header instance is 58px, but the PLP frame shows 66px and the theme ships `min-h-[66px]`. The theme value wins; 117px is not a valid offset (D-22)
- Vertical spacing is margin on the wrapper, padding only on an element that paints a background — the panel paints white, so it takes padding
