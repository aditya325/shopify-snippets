# PRD: 2.2 — Focus, Keyboard & State Transitions

**Phase:** Phase 2 — Modal Shell
**Priority:** P0
**Depends on:** 2.1 Modal Shell (Responsive)
**Estimated scope:** Small (1-3 files)

## Context

After 2.1 (`docs/roadmap-search/phase-2-modal-shell/2.1-modal-shell-responsive.md`), the shell renders
correctly on both breakpoints. `assets/search-modal.js` currently handles open, close, Escape, backdrop
click and a ⌘K/Ctrl+K shortcut, and focuses the input on open. It does **not** trap focus inside the
modal, and it does not return focus to the trigger on close — both required by Sprint §4.1. The loading
state currently renders `icon-spinner`, which §4.2 explicitly replaces with a fade. No design exists for
the loading state; it is built to house convention.

## Goal

The modal's interaction contract complete — focus trapped while open and returned on close, all three
close routes working, and the default ⇄ loading ⇄ results ⇄ cleared transitions running as fades with
no layout jump.

## Requirements

### Functional
- Focus moves into the input on open and is **trapped** inside the modal while it is open — Tab and Shift+Tab cycle within, nothing behind the modal is reachable
- Focus returns to the header search icon that opened it on close
- Closes on the close control, on Escape, and on a backdrop click — all three verified independently
- ⌘K / Ctrl+K continues to toggle the modal (existing behaviour, retained per D-20)
- Remove `icon-spinner` from the loading state; replace with a fade
- Loading is a fade with **no layout jump** — the panel must not resize between default groups and results
- Clearing the query returns the modal to its default state, including re-rendering Recent Search
- `body` scroll stays locked while open and is restored on close
- `aria-hidden`, `role="dialog"` and an accessible name are correct in both states

### Non-Functional
- `prefers-reduced-motion: reduce` disables the fade and swaps content instantly
- Accessible name on every icon-only control — close, clear
- Focus indicator visible on every focusable element inside the modal

## Approach

Extend `assets/search-modal.js` rather than rewriting it; the open/close/Escape/⌘K logic is sound and
the modal already sits at `z-[60]` above the `z-50` header. Implement the trap by querying focusable
descendants on open and handling `keydown` on Tab at the boundaries — do not install a library. Store
the triggering element in a variable at open time and call `.focus()` on it inside the existing
`setTimeout` in `closeModal`, so focus returns after the transition rather than during it. For "no
layout jump", the honest constraint is that the default panel and the results panel are different
heights by design (741 vs 551 ceilings); hold the panel's height stable across the swap by animating
opacity on the two content containers while the panel keeps its current height until the new content
settles. Since no design exists for the fade, use the house transition already used by the mega-menu
backdrop — 250ms `ease-out` with a `motion-reduce` escape — so search matches navigation rather than
inventing a second timing.

## Expected Output

- `assets/search-modal.js` — focus trap, focus return, state-transition orchestration
- `assets/predictive-search.js` — loading class handling changed from spinner to fade
- `snippets/search-modal.liquid` — spinner markup removed, ARIA attributes corrected

## Constraints

- No inline scripts; all JS in `assets/`, loaded `defer` from `sections/header.liquid`
- DOM targeting via `data-*` attributes, not class names. ⚠️ **Corrected:** `.search-modal-close` was converted to `[data-search-close]` by 2.1 on an `/assess` Critical. Only `.search-trigger` remains a class hook; new hooks are `data-*`
- The loading fade has no design reference (D-15, D-16); the house 250ms `ease-out` is the stated default and is recorded as a deviation, not presented as extracted
- Sprint §4.4: the cart drawer opens over the modal and the modal must stay open behind it — the focus trap must not fight the drawer's own focus management
