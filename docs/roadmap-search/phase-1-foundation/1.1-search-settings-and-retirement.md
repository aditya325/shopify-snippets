# PRD: 1.1 — Search Settings & Code Retirement

**Phase:** Phase 1 — Foundation
**Priority:** P0
**Depends on:** None — can start immediately
**Estimated scope:** Medium (4-7 files)

## Context

The search modal is `snippets/search-modal.liquid`, rendered from `sections/header.liquid:38`. It is a
snippet, not a section, so it has no schema of its own — all five of its existing settings live in the
global `"Search"` group in `config/settings_schema.json`. Two of the groups it renders are being
dropped: Trending (Sprint §1 confirms it discarded) and Recently Viewed (present in neither the design
nor the TDD). Nothing has been built for this sprint yet.

## Goal

The `"Search"` settings group in its final shape for this sprint, and the Trending and Recently Viewed
groups gone from code, settings and locales — so every later PRD reads a setting that exists and
renders into a modal with no dead groups in it.

## Requirements

### Functional
- Remove `trending_collections` and `trending_collections_heading` from the `"Search"` group
- Rename `best_sellers_products` → `popular_collection` (type `collection`)
- Rename `best_sellers_products_limit` → `popular_products_count`, changed from `number` to `range`, min 1, max 12, default 4
- Rename `best_sellers_products_heading` → `popular_heading`, changed from `richtext` to `text`, default `Popular Products`
- Add `search_recent_heading` (`text`, default `Recent Search`) and `search_concern_heading` (`text`, default `Browse by concern`)
- Add `search_concern_menu` (`link_list`) as the source for the Browse by concern chips
- Add `recent_searches_limit` (`range`, min 1, max 10, default 6)
- Add `search_results_count` (`range`, min 1, max 10, default 10)
- Add `no_results_text` (`richtext`, default `Sorry, no results found.`), `no_results_cta_label` (`text`, default `Shop All`), `no_results_cta_link` (`url`)
- Delete the Trending block from `snippets/search-modal.liquid` and the Recently Viewed render call
- Delete `snippets/search-modal-recently-viewed.liquid`, `assets/search-recently-viewed.js`, and its `<script>` tag in `sections/header.liquid`
- Remove the now-unused `search.trending` and `search.recently_viewed` keys from `locales/en.default.json`

### Non-Functional
- Renaming a setting ID orphans its stored value in `config/settings_data.json`. ⚠️ **Corrected during execution:** no search setting had a stored value — `current` holds 24 keys, none of them search, and there are no presets. Nothing was orphaned. The merchant **assigns** the Popular Products collection for the first time after deploy. Record as a handover note; never hand-edit `settings_data.json`

## Approach

Edit the `"Search"` group in `config/settings_schema.json` in place; the group already exists, so this
is an amend, not an addition. Keep setting IDs snake_case per theme convention and order them by the
group they drive (recent → concern → popular → results → no-results) so the customizer panel reads in
the same order as the modal. `range` is used wherever a count is merchant-tunable because it enforces
its own bounds, which `number` does not. Removal is a straight delete of the Trending `{%- if
settings.trending_collections != blank -%}` block and the `{%- render 'search-modal-recently-viewed'
-%}` call — both are already guarded, so the modal degrades safely if the order of operations slips.
Do not touch `sections/predictive-search.liquid` or `assets/predictive-search.js`; the API rewire is 1.2.

## Expected Output

- `config/settings_schema.json` — `"Search"` group in final shape, 11 settings
- `snippets/search-modal.liquid` — Trending block and Recently Viewed call removed
- `sections/header.liquid` — `search-recently-viewed.js` script tag removed
- `locales/en.default.json` — two dead keys removed
- Deleted: `snippets/search-modal-recently-viewed.liquid`, `assets/search-recently-viewed.js`
