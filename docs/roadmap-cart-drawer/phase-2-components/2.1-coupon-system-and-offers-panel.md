## Context

1.1 provides the shell (scroll region, footer). 0.1 provides `offers_list` (metaobject_list on `custom.offer`), `drawer_coupon_count`, and 3 real offer entries. No coupon UI exists today — the current footer only lists `cart.cart_level_discount_applications` read-only. Per TDD §5.13 and §8.3, this is the highest-effort styling in the sprint (F4) and should be built as one reusable snippet used in two places, not duplicated.

## Goal

One coupon-ticket snippet powers both the drawer's inline offer list and the full offers panel; a working discount-code input (empty/applied/remove) and an auto-applied coupon row, all backed by real Shopify discounts, not hardcoded data.

## Requirements

### Functional
- `snippets/coupon-ticket.liquid`: 368×68 ticket shape — dark-green rotated side tab ("20% OFF"), dashed divider, code + description — takes an `offer` object param, no hardcoded content
- Discount code row (§5.6): empty state (placeholder + Apply), applied state (code + Remove), submits through Shopify's cart discount endpoint
- Auto-applied coupon row (§5.8): visible only when ≥1 discount is applied, one chip per `cart.cart_level_discount_applications` entry, absent in the empty state
- Offers panel (§5.13): "See all" swaps the scroll region in place to 6 tickets from `offers_list` (not a new page/modal); "back" restores the drawer and its prior scroll position
- Drawer shows `drawer_coupon_count` tickets before "See all"

### Non-Functional
- No discount code is fetched from Shopify at runtime for the ticket list — content comes only from `offers_list`

## Approach

Extend `assets/cart-drawer.js` (do not replace) with a view-swap method that toggles a data attribute between "drawer" and "offers" content rather than remounting the element, and apply/remove-code handlers. Per TDD F2, confirm the exact Shopify cart API route for applying a discount code from a drawer without a page reload at the start of this PRD's execution — do not assume the endpoint. The ticket snippet is rendered identically in both surfaces per this theme's render-argument conventions (no filters in `{% render %}` args).
