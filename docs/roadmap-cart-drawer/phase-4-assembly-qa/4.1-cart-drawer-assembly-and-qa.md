## Context

Phases 1-3 built each piece in isolation: shell (1.1), coupon system (2.1), line item (2.2), milestone tracker (2.3), price summary/recommended (2.4), empty state (3.1). `assets/cart-drawer.js`'s `_morphSection` (lines 202-216) currently re-renders only `[data-cart-items]` and `[data-cart-footer]` on a cart mutation — TDD §8.2 requires 8 regions to re-render, most of which don't exist in that method yet.

## Goal

One working cart drawer where every piece from phases 1-3 is wired together, every §8.2 region re-renders correctly on any cart mutation, and the built drawer matches every acceptance criterion in TDD §11.

## Requirements

### Functional
- Extend `_morphSection` (or its equivalent) to also morph: header count badge, milestone tracker, gift-line presence, auto-applied coupon row, price summary — in addition to the existing items/footer regions
- Verify all 4 shell states (populated / discount applied / empty / offers panel) transition correctly end-to-end, not just in isolation
- Verify milestone crossing correctly attaches/detaches the gift line live and re-renders the affected line item and tracker together

### Non-Functional
- `theme check` 0 offenses
- No regression to add-to-cart flows elsewhere in the theme (product page, quick-add)

## Approach

This is integration work, not new components. Assemble all snippets from 1.1-3.1 into `sections/cart-drawer.liquid` in the correct order; extend the morph region list and gift attach/detach call sites in `assets/cart-drawer.js`. Work through TDD §11 as a literal checklist and §10 to confirm every excluded item stays absent — don't re-derive requirements from the Figma file directly, the prior PRDs already resolved ambiguity against it.
