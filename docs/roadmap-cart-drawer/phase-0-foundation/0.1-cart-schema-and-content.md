# PRD: 0.1 — Cart Schema & Content

**Phase:** docs/roadmap-cart-drawer/phase-0-foundation/0.1-cart-schema-and-content.md
**Priority:** P0
**Depends on:** None — can start immediately
**Estimated scope:** Small (1-3 files, plus admin content authoring)

## Context

`sections/cart-drawer.liquid` exists today with a minimal schema (`name` + `class` only, no settings). The TDD (`docs/tdds/amrutanjan-cart-drawer-sprint.md`, §7.1) specifies 14 new settings and one block type this sprint needs. The `custom.offer` metaobject definition **already exists live** (`gid://shopify/MetaobjectDefinition/13272580183`, fields `title`/`description`/`code`/`icon`) — created by the PDP sprint (see `docs/roadmap-pdp/status-log.md`) and reused here per TDD §7 rather than redefined (this resolves TDD OD2).

## Goal

Every setting, block type, and content entry the later phases render against exists and is populated with real values before any UI is built.

## Requirements

### Functional
- Add all 14 settings from TDD §7.1 to `sections/cart-drawer.liquid`'s schema with matching setting IDs (snake_case, exact names)
- Add a `milestone` block type: `threshold` (number), `reward_label` (text), `gift_product` (product)
- `offers_list` is `type: metaobject_list` scoped to `custom.offer` — do not create a new metaobject definition
- Author 3 new `custom.offer` entries: `ENDYEARSALE`, `WELCOME50`, `AM699` (title/description/code populated; `icon` left blank, matching the existing two entries' precedent)
- Configure 3 `milestone` blocks matching the TDD §5.3 example: 499/10%, 699/15%, 999/20%

### Non-Functional
- Setting IDs must match TDD §7.1 literally — downstream PRDs reference them by name

## Approach

Edit `sections/cart-drawer.liquid`'s `{% schema %}` block directly, following `shopify-theme-toolkit:section-standards` for setting/block conventions. Author the 3 metaobject entries via Shopify Admin GraphQL (`metaobjectCreate`), mirroring the pattern `docs/roadmap-pdp/phase-0-foundation/0.1-pdp-data-model.md` used — record the resulting GIDs/handles in this PRD's execution log (`.buildspace/artifacts/`), since `docs/roadmap-pdp/status-log.md` is the only tracked record for that phase's identifiers and this one should follow suit.

## Expected Output

- `sections/cart-drawer.liquid` — schema additions only, no markup changes
- 3 new `custom.offer` metaobject entries, GIDs recorded in the execution log
- 3 `milestone` blocks configured on the section

## Dependencies

### Upstream (must be done first)
- None

### Downstream (unblocked by this phase)
- 1.1, 2.1, 2.3, 2.4, 3.1 all read these settings and content

## Constraints

- Do not create a second `custom.offer`-shaped definition — reuse the existing GID
- TDD D2 (reached-milestone icon asset) and D3 (140×140 empty-state illustration) are not supplied yet — `empty_illustration` must accept a blank value gracefully; do not block this PRD on their arrival, just record them as open inputs
