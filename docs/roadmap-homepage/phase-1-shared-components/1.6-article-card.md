# PRD: 1.6 — Article Card

**Phase:** Phase 1 — Shared Components
**Priority:** P1
**Depends on:** 0.2, 0.4, 0.5 metafield-definitions, 1.1 icon-set
**Estimated scope:** Small (2-3 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=108-11414
- **Mobile:** Same file — node-id=108-10684
- **Frames:** Wellness Simplified (`108:12632` / `108:11030`) — four `Blog Post` instances

## Context

`snippets/article-card.liquid` already exists in themex and is rendered from one place,
`sections/blog.liquid`, which passes `article` and `show_author`. Sprint §4.16 describes it as
a "new article-card snippet" with a contract that does not match the existing file. The
approved decision is to overwrite in place.

Blast radius is small — one call site — but the blog template must keep working.

The Figma card shows an image with a gradient wash
(`linear-gradient(#17171700 0%, #171717 100%)`), a badge, a title in Space Grotesk 18 Medium,
meta text, and a "Read →" link.

## Goal

One article-card snippet matching the design, driven by article object fields plus the
`read_time` metafield, with `sections/blog.liquid` still rendering correctly.

## Requirements

### Functional
- Fields per Sprint §4.16: badge = blog title (derived), image from the article, title (1-line clamp), date from `published_at`, read time from the `read_time` metafield (0.5), "Read" label with embedded arrow
- **Whole card is clickable** — linking to the article
- Read label text is passed in from the section, not hardcoded
- Keeps the existing `article` parameter name so `sections/blog.liquid` needs no change; `show_author` must still be accepted or the blog template updated in the same PR
- Renders correctly when `read_time` is unset — omit the element, do not print an empty separator
- Gradient wash over the image as measured

### Non-Functional
- Image via `snippets/image.liquid` as a `<picture>`, lazy + `decoding="async"` below the fold
- The whole-card link must not nest interactive elements — one anchor, not an anchor inside an anchor

## Approach

Rewrite in place, preserving the `article` parameter. Check `sections/blog.liquid` for its
`show_author` usage first: either keep supporting the flag, or drop it and update the blog
section in this same PR. Do not leave the blog template passing a parameter the snippet ignores.

Use the stretched-link pattern already present in `snippets/product-card.liquid` (the existing
themex file documents it in its `{% doc %}` block) so the whole card is clickable without
wrapping nested anchors — the "Read →" affordance is visual, sitting inside the same single
link.

The gradient wash is a CSS overlay on a positioned container, not a second image and not a CSS
background-image on the `<img>` — Global Standards §7 forbids CSS background images for
content, but a gradient overlay layer is fine.

Date formatting should use Liquid's `date` filter against `published_at` with a format the
merchant does not have to configure; match what the design shows.

## Expected Output

- `snippets/article-card.liquid` — rewritten with `{% doc %}`
- `assets/base.css` — gradient wash and line-clamp styles if not expressible as utilities
- `sections/blog.liquid` — updated only if `show_author` is dropped

## Dependencies

- 1.1 icon-set — the Read arrow
- 0.2, 0.4 — colour and type tokens

### Downstream (unblocked by this phase)
- 2.13 featured-blogs

## Constraints

- Overwrite in place; `sections/blog.liquid` must keep working
- Badge text is derived from the blog title, not a merchant field
- `read_time` type is fixed by 0.5 — follow it rather than assuming integer or string
- No nested anchors
- Use `{% render %}`, never `{% include %}`
