**Phase:** Phase 1 — Shared Components
**Priority:** P0
**Depends on:** 0.2, 0.4, 0.5 metafield-definitions, 1.1 icon-set, 1.2 button-snippet
**Estimated scope:** Large (8+ files including call-site regression)

- **Mobile:** Same file — node-id=108-10684

## Context

`snippets/product-card.liquid` already exists (103 lines) and is rendered from **five**
sections: `collection.liquid`, `search.liquid`, `product-recommendations.liquid`,
`recently-viewed-products.liquid` and `featured-collection.liquid`. All five pass only
`card_product`; one also passes `lazy_load`. The approved decision is to **overwrite in place**,
which is what Global Standards §6.3 intends — one card across every product grid and slider.

That makes this the highest-blast-radius PRD in the roadmap: four pages outside the homepage
change appearance when it lands.

## Goal

One product-card snippet matching the design, driven entirely by the 0.5 metafields, reused by
both new homepage sections and all five existing call sites without breaking them.

## Requirements

### Functional
- Fields per Sprint §4.5: badge (`product_badge`), wishlist icon, image, category badge (`category_label` + `highlight_color`), title (2-line clamp), highlight text (`highlight_text` + `highlight_color`, 1-line clamp), rating, price, Add to Cart
- Accepts `show_featured_image` and `hide_price` flags, both defaulting so the five existing call sites render sensibly with no argument changes
- **Image logic:** `show_featured_image` ON → featured image. OFF → `card_image` metafield with the radiator background behind it; a product with no `card_image` falls back to featured image **with no radiator**
- **Price:** sale + compare-at slashed, shown only when compare-at > price; discount percent computed in Liquid, formatted `(X%)`, coloured `#D93807`
- **Add to Cart:** AJAX through the existing themex `product-form` flow, unchanged, single-variant products
- **Wishlist icon ships inert** — rendered but non-functional pending OD1
- **Rating** is a Judge.me preview badge, blocked by D2 — render a guarded no-op that produces nothing until the app is present, never a broken widget or reserved empty space
- Fonts per the §2.1 normalization table: title DM Sans Medium 16, Add to Cart DM Sans SemiBold 14, sale price DM Sans Bold 16

### Non-Functional
- Single evaluation criterion (Global Standards §6.4) — N cards on a page each initialise once
- Card image lazy below the fold, `decoding="async"`; rendered via `snippets/image.liquid` as a `<picture>`, never a CSS background

## Approach

Rewrite `snippets/product-card.liquid` in place, keeping the existing parameter name
`card_product` so the five call sites keep working untouched. Add new parameters with `default:`
values chosen so that a bare `{% render 'product-card', card_product: product %}` produces the
correct card for a collection grid.

Every metafield read must tolerate absence — a product with no `product_badge`, no
`category_label`, no `highlight_text` and no `card_image` must render a clean card, not empty
boxes or stray separators. Wrap each optional element in a blank check.

The radiator background is resolved by OD2 in 0.5; read that decision rather than assuming.
Whichever it is, the radiator renders only in the `show_featured_image: false` + `card_image`
present case.

For the Judge.me rating, guard on the app's presence and emit nothing when absent. Do not
reserve vertical space for it — reserving space produces a visible gap on every card until D2
lands.

After the rewrite, walk all five call sites at mobile and desktop. This regression sweep is part
of the PRD, not a follow-up.

## Expected Output

- `snippets/product-card.liquid` — rewritten
- `assets/base.css` — card styles that Tailwind utilities cannot express (line clamps, radiator positioning)
- `assets/product-card.js` — only if interaction is needed beyond the existing product-form flow
- Regression verification across `collection`, `search`, `product-recommendations`, `recently-viewed-products`, `featured-collection`

## Constraints

- Overwrite in place; the five existing call sites must not need argument changes
- All card data from metafields, never hardcoded (Sprint §3)
- Single-variant products only
- Existing AJAX add-to-cart flow is not modified (Sprint §1)
- Wishlist inert until OD1; rating absent until D2
- The hidden Figma `Product Card` frame is not the spec
