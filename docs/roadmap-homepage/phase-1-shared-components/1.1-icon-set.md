## Context

`snippets/` already holds 15 `icon-*` snippets from themex, including `icon-arrow-left`,
`icon-arrow-right` and `icon-chevron-down/left/right`. The Amrutanjan design uses a specific
arrow — rendered in Figma as a 14×14 frame containing two vectors at **1.3px stroke**, appearing
inside every primary and secondary CTA — and a 10×10 chevron inside the discount-banner pills.
Whether the existing themex icons match these shapes has not been verified.

Global Standards §2 requires decorative arrows and chevrons to be embedded in code as icon
snippets; only merchant-supplied icons come through `image_picker`.

## Goal

Every decorative icon the homepage needs exists as a reusable snippet that inherits colour from
`currentColor` and sizes from its container, with the existing themex icons reused wherever
they already match.

## Requirements

### Functional
- Audit all 15 existing `icon-*` snippets against the design before creating anything new — reuse over duplicate
- Provide the CTA arrow (14×14, 1.3px stroke) used by hero buttons, the accent CTA and card links
- Provide the pill chevron (10×10) used by featured-discounts
- Provide the card arrow used by shop-by-lifestyle and shop-by-category
- All icons use `currentColor` for stroke/fill so a parent's text colour drives them
- All icons accept a size via class rather than hardcoded width/height attributes
- Icons are `aria-hidden="true"` when decorative

### Non-Functional
- Inline SVG, not sprite sheets or icon fonts — matches the existing themex pattern

## Approach

Start with the audit. Open each existing `icon-*` snippet and compare it against the vectors in
`.buildspace/artifacts/home-page/design-context.md` — the element trees record every vector's
dimensions and stroke width. Where an existing icon matches, use it and note that in the PR;
only create a new snippet where the shape genuinely differs.

Follow the existing snippet convention exactly: a `{% doc %}` block, then inline SVG with
`stroke="currentColor"`, `fill="none"` where appropriate, and no hardcoded colour. Size via a
`class` parameter defaulting to a sensible value rather than baking `width`/`height` into the
SVG element.

Do not create icons speculatively. Social icons in the footer are merchant-supplied SVGs via
`image_picker` per Sprint §4.17, and USP icons in subscribe-letter and footer are also
`image_picker` — none of those belong here.

## Expected Output

- `snippets/icon-chevron-pill.liquid` (or reuse, documented)
- Any further icon snippets the audit proves are genuinely missing
- A short audit note in the PR listing each existing icon and reuse/replace verdict
