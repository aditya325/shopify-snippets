# PRD: 1.3 — Section Header & Smile Underline

**Phase:** Phase 1 — Shared Components
**Priority:** P0
**Depends on:** 0.2 colour-tokens, 0.3 spacing-tokens, 0.4 typography
**Estimated scope:** Small (2-3 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=108-11414
- **Mobile:** Same file — node-id=108-10684
- **Frames:** The arc appears in nearly every section heading — clearest in Bestsellers (`108:11497`), Curated Wellness Bundles (`108:12268`), Reviews (`108:12609`). The white variant is on the mobile hero (`108:10713`).

## Context

Eleven of the thirteen Phase 2 sections plus both app wrappers open with the same pattern: a
richtext heading with a hand-drawn arc underlining one or two words. Global Standards §6.2 and
Sprint §2.4 specify the mechanism precisely, including the extracted SVG path. No shared
heading snippet exists in the theme today.

The arc is one vector reused at widths from 72px to 175px at 2px stroke, `#F4C430` by default
and white on the mobile hero banner.

## Goal

One `snippets/section-header.liquid` that renders a richtext heading at the correct type token
and draws the smile underline beneath any word the merchant italicises, stretching to that
word's width and wrapping as a single unit.

## Requirements

### Functional
- Renders a richtext heading at `section-heading` (Space Grotesk Bold 34 D / 24 M)
- Merchant marks word(s) with **italic** in richtext; CSS targets the `<em>` inside a wrapper carrying `has-smile-underline`
- Arc drawn on an `::after` pseudo-element via **CSS mask** using the extracted SVG, `preserveAspectRatio: none` so it stretches to the marked span's width
- Colour from `--underline-color`, default `#F4C430`, overridable per section (white variant required)
- The marked span is `display: inline-block` so word + underline wrap to a new line as one unit
- The italic marker must **not** render as italic text — the `<em>` is a marker, not a style
- Accepts an optional heading level parameter so the homepage has one `<h1>` and the rest are `<h2>`
- Renders nothing when the heading is blank

### Non-Functional
- No layout shift as the mask paints
- The underline is decorative and must not be announced by screen readers

## Approach

The extracted path is `M0.21 0.98 C0.21 0.98 32.06 7.98 67.69 7.98 C103.33 7.98 138.21 0.98
138.21 0.98` on `viewBox 0 0 139 9` at `stroke-width 2`. Inline it as a data-URI in
`assets/base.css` and apply it with `mask-image` / `-webkit-mask-image` plus
`mask-size: 100% 100%`, so the `::after` box is painted in `background-color:
var(--underline-color)` and the mask cuts the arc shape. This is what makes one colour variable
drive every instance.

Set `font-style: normal` on the `<em>` explicitly — merchants are using italic as a semantic
marker and the design shows no italic text. Position the `::after` absolutely against an
`inline-block` `<em>` with `position: relative`, offset below the text baseline by the measured
gap.

Note that Sprint §4.4 reuses the same asset for the **tabbed-product-collection active tab**
via a class, with no italic marker. Expose that as a separate class hook on the same base rule
so the tab state does not need its own SVG copy.

Per-section colour override is a CSS custom property set on the section wrapper, not a new
class — that keeps the number of variants at one.

## Expected Output

- `snippets/section-header.liquid` — richtext heading + wrapper class, with `{% doc %}`
- `assets/base.css` — `.has-smile-underline em::after` rule, masked SVG data-URI, `--underline-color` default, and the class-only variant for tab states

## Dependencies

### Upstream (must be done first)
- 0.2 colour-tokens — accent colour default
- 0.3 spacing-tokens — header sits inside the section wrapper
- 0.4 typography — `section-heading` token

### Downstream (unblocked by this phase)
- 2.1–2.13 (all except 2.5 announcement-banner and 2.6 media-carousel, which have no heading)
- 3.1 see-it-in-action, 3.2 reviews — both provide the standard header

## Constraints

- Merchants mark underline via richtext italic; no separate "underline this word" schema field
- One shared arc asset — do not duplicate the SVG per section
- Non-utility CSS goes in `assets/base.css`
- Heading is richtext, so line breaks are authored by the merchant, never forced by max-width

## Acceptance Criteria

- [ ] A richtext heading with one italicised word renders that word underlined by the arc
- [ ] The arc stretches to the marked span's width — verified at both a short word (~72px) and a long phrase (~175px)
- [ ] The italicised word renders upright, not italic
- [ ] `--underline-color` override produces the white variant on a dark background
- [ ] Word plus underline wrap to a new line as one unit at narrow widths
- [ ] The tab-state class draws the same arc without an italic marker
- [ ] Heading level is settable; blank heading renders nothing
- [ ] The `::after` is not announced by a screen reader
