## Context

Sprint §4.13. A stats row — three claims, each a value, a label and an optional icon. The plus
glyph and the dividers between claims render **in code**, not as merchant fields.

Two normalization rows from Sprint §2.1 apply here: the plus glyph is Inter Medium 36 desktop /
26 mobile in Figma and normalizes to **DM Sans Medium 36 / 26**; the rating value is DM Sans
Bold 40 desktop / 22 mobile per the extraction.

## Goal

A blocks-based stats row rendering any number of claims with correct type, the code-rendered
plus glyph and dividers, matching the design at both breakpoints.

## Requirements

### Functional
- Section-level richtext heading, underline-enabled
- Block type `claim` with: claim title (text), claim value (text), claim icon (`image_picker`)
- Plus glyph and dividers rendered in code — not merchant fields, not part of the value string
- Any block count self-adjusts; no `max_blocks`
- Measured padding: desktop 32 vertical / 60 sides, gap **160**; mobile 24 vertical / 20 sides, gap 24

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). The `Measured padding:` line above states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- Section-level `margin_top` / `margin_bottom`; `presets` with three default claim blocks

### Non-Functional
- Icons via `image_picker` render as `<picture>` through `snippets/image.liquid`, lazy below the fold

## Approach

Standard section skeleton plus a block loop. The desktop gap of 160px is unusually large and is
measured — apply it as-is rather than substituting a scale step.

The plus glyph is a text character rendered in code adjacent to the value (the design shows
"2M+", "130+" as value plus a separately-styled glyph). Do not ask the merchant to type the `+`
into the value field, and do not concatenate it into the value string — it is styled
differently from the value, at DM Sans Medium 36/26 versus the value's own weight and size.
Render it as its own element and let it be present or absent per block based on whether the
design shows it. Check the extraction: the desktop rating claim ("4.8") has no plus, while the
stat claims do — so this needs a per-block toggle or a derived rule, and a per-block checkbox is
the honest choice.

Dividers sit between claims and must not render after the last one — use `forloop.last`.

Take the exact per-element type from the "Trusted By Millions" typography table in
`design-context.md` rather than the Sprint summary.
