## Context

Sprint §4.4. The Bestseller section — tabs generated from a merchant-selected collection list,
rendering the first 4 products of the active collection through the 1.5 product-card snippet.

Two derived behaviours, neither merchant-authored: **tab label = collection title**, and **View
All link = active tab's collection URL**. Only the View All *label* is a merchant field.

The active tab carries the smile underline via the shared asset class from 1.3 — **no italic
marker needed**, it is applied as a class. 1.3 is required to expose that class-only variant.

Extraction shows the desktop header as two tab labels ("Just Dropped", "Best Sellers") at Space
Grotesk Bold 34 with the arc beneath the active one; mobile is the same at 24 with a 2-column
product grid.

## Goal

A tabbed product section where tabs derive from selected collections, the active tab is
underlined, and the first four products of the active collection render as product cards.

## Requirements

### Functional
- Section-level: collections (`collection_list`, one tab per collection), show product featured image in cards (`checkbox`), View All label (`text`)
- Tab label is **derived** from `collection.title`
- Renders the **first 4 products** of the active collection via `snippets/product-card.liquid`
- `show_featured_image` flag passes through to the card
- View All links to the active collection's URL, derived — not a merchant `url` field
- Active tab gets the smile underline via the 1.3 class-only variant
- Tab switching happens client-side without a page reload
- Measured padding: desktop 32 vertical / 60 sides, gap 24; mobile 24 vertical / 20 sides, gap 20

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). The `Measured padding:` line above states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- `presets`; no `max_blocks`

### Non-Functional
- Tabs are keyboard-operable with proper `role="tablist"` / `role="tab"` / `aria-selected` semantics
- All collections' products render server-side and are shown/hidden client-side, so switching is instant and works without JS as a progressive-enhancement fallback

## Approach

Render every selected collection's first four products into the DOM up front, each panel hidden
except the active one, and toggle visibility on tab click. This keeps switching instant, avoids
a fetch, and degrades gracefully — with JS disabled the first panel is still visible. The
alternative (Section Rendering API fetch per tab) adds latency and a failure mode for no visible
benefit at four products per tab.

Wrap tab behaviour in a Web Component with the `customElements.get()` guard. Use real ARIA tab
semantics — `role="tablist"` on the container, `role="tab"` with `aria-selected` and
`aria-controls` on each tab, `role="tabpanel"` on each panel — and support arrow-key navigation
between tabs.

The View All link must re-target when the tab changes, since it points at the active
collection's URL. Either update `href` in the tab handler or render one View All per panel and
show it with its panel; the latter is simpler and needs no JS.

Guard the empty cases: a selected collection with fewer than four products renders what it has;
a collection with none renders an empty-state rather than a broken grid; no collections selected
renders nothing.
