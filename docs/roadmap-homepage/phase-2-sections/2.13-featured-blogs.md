## Context

Sprint §4.16. Wellness Simplified — blocks pick individual articles, each rendered through the
1.6 article-card snippet. The section is full bleed on the sides.

Two things are notable. The **Read label is section-level and applied to all cards**, not
per-block — so it is authored once. And **View All Tips links to a fixed URL per decision
(D6)** — that decision is referenced in §4.16 but D6 does not appear in the Sprint §5
dependency table, so the URL itself must be confirmed before this ships.

Extraction shows four `Blog Post` instances at 180px wide inside a 350px mobile container —
meaning mobile overflows and scrolls horizontally, same pattern as 2.4. This section is not in
the Global Standards §6.4 carousel list, so it is native scroll, not Embla.

Type note from Sprint §2.1: the Read link on mobile is Manrope SemiBold 14 in Figma and
normalizes to **DM Sans SemiBold 14**. Section heading is Space Grotesk Medium 34 desktop
normalizing to Bold.

## Goal

A full-bleed article section where merchants pick specific articles, rendered as article cards,
with a shared Read label and a View All Tips CTA.

## Requirements

### Functional
- Section-level: heading (`richtext`, underline-enabled), Read label (`text`, applied to all cards)
- Block type `article_block` with a single `article` field — one per card
- Cards render via `snippets/article-card.liquid` from 1.6, receiving the section's Read label
- View All Tips button links to a fixed URL (D6) — expose it as a section `url` setting defaulting to the confirmed value rather than hardcoding
- Full bleed on the sides
- Mobile: horizontal scroll container, cards at the measured 180px — **not** Embla
- Measured padding: desktop 32 vertical, full-bleed sides; mobile 24 top / 44 bottom

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). The `Measured padding:` line above states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- `presets` with four article blocks; no `max_blocks`

### Non-Functional
- Below the fold — card images lazy + `decoding="async"`
- Horizontal scroll uses `scroll-snap`, hidden scrollbar, keyboard scrolling intact

## Approach

Standard blocks section. The Read label is section-level, so read it once and pass it into every
`{% render 'article-card' %}` call rather than duplicating a field per block.

**Resolve D6 before shipping.** §4.16 says the View All Tips URL is fixed by decision, but no
such decision is recorded in the Sprint §5 table. Rather than hardcoding a guess, expose it as a
section-level `url` setting whose preset default is the confirmed value. That satisfies the
"fixed per decision" intent while keeping the section merchant-editable and unblocking the build
if the answer is slow. Flag the resolution in the PR.

Mobile horizontal scroll follows the same pattern as 2.4 — reuse those `assets/base.css` rules
rather than writing a second scroll-snap implementation. If 2.4 landed first, factor the rule
into a shared class.

The mobile bottom padding of 44px is an explicit §5.2 exception and is intentional; do not
normalise it to the 24px standard.

Guard the empty case: an article block with no article selected must render nothing rather than
an empty card.
