## Context

Sprint §4.8. Upselling banners — the simplest carousel section, with no heading and no text
fields at all. Each block is purely a media slot.

The responsive rule is **conditional on block count**, the trickiest behaviour in this section:
mobile is always Embla at 1 slide per view with dots overlaid on the blocks; desktop
is a static flex row up to 3 blocks, and only **more than 3** enables Embla at 3.2 slides per
view. This is the section that proves the "activate only above N blocks" mode.

## Goal

A heading-less media banner row that is a static flex row on desktop up to 3 blocks, a 3.2-per-
view carousel beyond that, and always a 1-per-view dotted carousel on mobile.

## Requirements

### Functional
- Block type `banner` with only: image (`image_picker`), video (`video`)
- Video takes priority over image; poster from `video.preview_image`
- Mobile: always Embla, 1 slide per view, dots **overlaid on the blocks** rather than below
- Desktop: static flex row at ≤3 blocks; Embla at 3.2 slides per view when >3
- Measured padding: desktop 0 vertical / 60 sides, gap 20; mobile 0 vertical / 10 sides, gap 10

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- No section heading, no text — this section has no `section-header`
- `presets` with three default blocks; no `max_blocks`

### Non-Functional
- Images as `<picture>` via `snippets/image.liquid` with separate desktop and mobile sources
- Below the fold, so everything is `loading="lazy"` + `decoding="async"`
- Video muted, `playsinline`, looped, lazy-initialised near viewport

## Approach

Write `assets/media-carousel.js` following the shape established in 2.5. Two conditions drive
activation: mobile is always on, desktop only above 3 blocks. Emit the block count from Liquid as
`data-item-count` and read it in the section's own JS:

```js
const shouldActivate = () => !isDesktop() || itemCount > 3;
```

The desktop teardown case matters — at ≤3 blocks the desktop must be a genuine static flex row
with no leftover Embla transform when the viewport crosses from mobile to desktop. This section
owns its own `matchMedia` listener and `embla.destroy()` call; verify the crossing in both
directions rather than assuming.

Dots overlay the blocks on mobile, so they need a positioned container and enough contrast
against whatever image sits behind them. Give them a subtle backdrop or a shadow rather than
relying on the artwork being dark.

Since this section is pure media with no text, its accessibility rests entirely on alt text —
make sure `image.liquid` receives meaningful alt from the merchant's uploaded asset, and that
the carousel exposes slide position to assistive technology.

## Expected Output

- `sections/media-carousel.liquid` — section with `{% schema %}`, `banner` block type and `presets`
- `assets/media-carousel.js` — standalone: `shouldActivate = () => !isDesktop() || itemCount > 3`, own matchMedia teardown, own dot block
- `assets/base.css` — overlaid dot positioning

## Constraints

- Owns a complete standalone JS file using the Embla globals vendored by 0.6. No shared module, base class or helper — duplication across the five carousel sections is accepted by decision. Boots on `DOMContentLoaded`
- Video beats image wherever both are set
- No CSS background images
- No heading — do not add one for consistency's sake; the design has none

## Acceptance Criteria

- [ ] Mobile always renders a 1-per-view carousel with dots overlaid on the blocks
- [ ] Desktop with 3 blocks renders a static flex row, no Embla instance
- [ ] Desktop with 4+ blocks renders a 3.2-per-view carousel
- [ ] Crossing the breakpoint from mobile to desktop at ≤3 blocks fully tears down the carousel with no leftover transform
- [ ] Measured padding and gaps correct at both breakpoints
- [ ] Video renders in place of image when both are set
- [ ] Dots are legible against a light banner image
- [ ] Dots are keyboard-operable with accessible labels and slide position exposed
- [ ] Alt text flows through from the merchant's uploaded image
- [ ] Section addable from the theme editor with three default blocks
