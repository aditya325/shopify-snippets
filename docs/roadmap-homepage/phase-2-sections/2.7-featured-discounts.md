## Context

Sprint §4.2. Three promo banners, each on its own gradient. The extraction confirms the three
measured gradients: `linear-gradient(#28BCC6 → #00949E)`, `linear-gradient(#FF972D → #E6790F)`
and `linear-gradient(#28BCF9 → #0094D1)`. Global Standards §4 lists the banner colour set as
**merchant-set per block**, not global tokens — so these are defaults on the preset, not
hardcoded values.

The whole block is one link; the "Shop Now" CTA with its embedded chevron is **visual only**
inside it, not a separate anchor.

Type note from Sprint §2.1: the Shop Now pill is Inter Bold 12 desktop / 10 mobile in Figma and
normalizes to **DM Sans Bold 12 / 10**. The offer number is Space Grotesk Bold 42 / 32.

## Goal

A blocks-based promo banner row — flex-1 blocks on desktop that self-adjust to any count, a
1.3-per-view carousel on mobile — with per-block gradients, decorative leaf, and whole-block
linking.

## Requirements

### Functional
- Block type `discount` with: background colour (`color_background`, covers solid **and** gradient), background image (`image_picker`, priority over colour), leaf image (`image_picker`, decorative, positioned top-right in code), category text (`text`), discount title (`richtext`), tagline (`text`), button label (`text`), button link (`url`)
- Desktop: blocks in a row, each `flex-1`; any block count self-adjusts
- Mobile: Embla at **1.3 slides per view**
- Whole block is the link (target = button link); the CTA pill is visual only, with its chevron from 1.1
- **Hover (F3, resolved):** the block itself has no hover state — cards never do. On block hover the pill alone fades to `opacity: 0.9` over 150ms ease. No colour change. Because the pill is a non-interactive span, the rule is block-triggered (`.block:hover .pill`), not `.pill:hover`.
- Background image takes priority over background colour
- Measured padding: desktop 20 top / 20 sides / 32 bottom, gap 20; mobile 8 all sides, gap 8

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- `presets` with three blocks carrying the measured gradients as defaults; no `max_blocks`

### Non-Functional
- Leaf image is decorative — `alt=""` and `aria-hidden`
- Corner radius per design, taken from the extraction

## Approach

Write `assets/featured-discounts.js` following the shape established in 2.5. Mobile is a 1.3-per-view
carousel; desktop is a plain `flex-1` row needing no carousel at any count, so `shouldActivate`
is simply `() => !isDesktop()`. The section owns its own `matchMedia` listener and `destroy()`.

The whole-block-link plus visual-pill combination must not produce nested anchors. Wrap the
block content in a single `<a>` and render the pill as a `<span>` styled like a button — use the
1.2 button snippet's `pill` variant classes but not its anchor output. If the snippet cannot
emit a non-anchor, add a parameter for that rather than duplicating the styles.

`color_background` handles both solid and gradient, so a single field covers every case. Apply
it as an inline style; Tailwind cannot generate arbitrary merchant gradients. Background image
overrides it — check image presence first and fall through to the colour.

The leaf sits top-right and bleeds outside the block bounds in the design (the extraction shows
it at a negative offset), so the block needs `overflow: visible` or a deliberately clipped
treatment — check the screenshots and match.
