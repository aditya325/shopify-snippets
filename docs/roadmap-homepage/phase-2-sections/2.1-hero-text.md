## Context

After Phase 1, the section-header snippet, smile underline, type scale and spacing wrapper all
exist. This is the simplest section in the roadmap and is deliberately first — it exercises the
full Phase 0 + Phase 1 foundation end to end with almost no section-specific logic, so any
problem in the tokens, the underline or the wrapper surfaces here before twelve more sections
depend on them.

Sprint §4.3: a single richtext strip. Line breaks are authored in the richtext, **never** forced
by a max-width.

## Goal

A full-bleed section rendering one richtext tagline at the `strip-heading` token, with smile
underline support, in the theme editor as an addable section.

## Requirements

### Functional
- One section-level `richtext` field, underline-enabled
- Type: Space Grotesk Bold 38 desktop / 26 mobile (`strip-heading` token)
- Full-bleed horizontally — no side padding, no container
- Measured padding: desktop 32 bottom; mobile 12 top / 24 bottom

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). The `Measured padding:` line above states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- Section-level `margin_top` / `margin_bottom` range settings that override the measured defaults
- `presets` entry so it is addable in the theme editor
- Renders nothing when the richtext is blank

### Non-Functional
- No layout shift; the strip is above or near the fold on most viewports

## Approach

A thin section: the 0.3 spacing wrapper in its full-bleed variant, then
`{% render 'section-header' %}` with the `strip-heading` type token and the heading level set to
`<h2>` (the hero owns the page's `<h1>`).

The critical detail is that line breaks come from the merchant's richtext. Do **not** apply a
`max-width` to force wrapping — the design's two-line break is authored content, and a
max-width would produce different breaks at different viewports. Let the richtext's own markup
control it.

Take exact padding and line-height from `design-context.md` under "Trusted Relief Marquee"
rather than from the Sprint summary, since the extraction records measured per-viewport values.

## Expected Output

- No new JS; no new CSS unless the full-bleed variant needs it

## Constraints

- Line breaks authored in richtext; no forced max-width (Sprint §4.3)
- Full bleed — no side padding at any breakpoint
- Nothing hardcoded; the tagline is entirely merchant-editable
- Blocks are not used in this section

## Acceptance Criteria

- [ ] Renders at Space Grotesk Bold 38 desktop / 26 mobile

- [ ] Full bleed at 390, 768 and 1440 with zero horizontal padding
- [ ] Measured padding correct: 32 bottom desktop; 12 top / 24 bottom mobile
- [ ] `margin_top` / `margin_bottom` settings override the defaults
- [ ] Merchant-authored line breaks are respected verbatim at every viewport
- [ ] Section is addable from the theme editor via its preset
- [ ] Blank richtext renders nothing — no empty section box
