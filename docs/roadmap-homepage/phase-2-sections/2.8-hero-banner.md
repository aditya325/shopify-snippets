## Context

Sprint §4.1. The most consequential section on the page: it is the **LCP candidate** and it
**overwrites the existing `sections/hero-banner.liquid`**, a themex section with entirely
different settings (`subheading`, `heading`, `text_alignment`, `overlay_opacity`,
`background_color`). Its only reference is `templates/index.json`, which 5.1 replaces — so the
overwrite is safe, but the old settings must not be carried forward.

Extraction: desktop is a 1400×620 rounded card (radius 20) on `#FDE047` inside a 1440 frame with
20px sides and 8px top; mobile is 374×480 (radius 12) with 8px sides. Hero title is Space
Grotesk Bold 56/74 desktop, 32/40.83 mobile. The eyebrow pill is `#F4C430`, DM Sans SemiBold
12 uppercase at 2px letter-spacing desktop / 10px mobile. Two CTAs — primary solid `#466E2E`
radius 12 desktop / 6 mobile, secondary outline 1px `#466E2E`.

## Goal

A full-width Embla hero carousel, one block per slide, dot pagination, 5-second auto-advance,
with the first slide image optimised as the LCP element.

## Requirements

### Functional
- Block per slide with: desktop image, mobile image, desktop video, mobile video, badge text, badge text colour, badge background colour, heading (`richtext`, underline-enabled), description (`richtext`), primary button label/link/bg/text colours, secondary button label/link/text colour
- Video takes priority over images; poster from `video.preview_image`
- Embla carousel, dot pagination, **auto-advance every 5 seconds**
- Hero heading supports the **white** smile-underline variant (`--underline-color: white`)
- Button arrows from 1.1, embedded in code, never merchant fields
- Measured padding: desktop 8 top / 20 sides; mobile 8 top / 8 sides

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- Button radius: 12 desktop / 6 mobile (F1 — as-designed per placement)
- Secondary button stroke follows its text colour
- `presets` with one slide; no `max_blocks`

### Non-Functional
- **First slide image is the LCP candidate**: `loading="eager"`, `fetchpriority="high"`, and preloaded. Every subsequent slide is lazy.
- Autoplay pauses on hover/focus and respects `prefers-reduced-motion`
- Hero heading is the page `<h1>`; subsequent slides' headings must not each be `<h1>`

## Approach

Delete the themex hero-banner body and rewrite the schema from scratch — do not attempt to
migrate the old settings, and do not leave orphaned settings in the schema. 5.1 replaces
`index.json`, so no data migration is needed.

The LCP work is the part most likely to be got wrong. Only the **first** slide gets eager +
`fetchpriority="high"`; giving every slide eager loading would load five hero images on first
paint and make LCP worse. Preload only the first slide's image, and only the correct viewport's
source — use `snippets/image-preloads.liquid` as the precedent, and preload the mobile source at
mobile widths, not both.

Heading level needs care: only the first slide should render `<h1>`. Pass the heading level into
`section-header` based on `forloop.first`, or render slide headings as `<h2>` and give the
section an sr-only `<h1>`. Pick one and document it.

The white underline variant is set by overriding `--underline-color` on the hero wrapper — the
1.3 snippet already supports this; do not add a second CSS rule.

Write `assets/hero-banner.js` following the shape established in 2.5: autoplay plugin at 5000ms
with hover and focus pause, loop on, dots, one slide per view at both breakpoints. No conditional
activation — the hero is always a carousel when it has more than one slide.

## Expected Output

- `sections/hero-banner.liquid` — fully rewritten with `{% schema %}`, slide block type and `presets`
- `layout/theme.liquid` or `snippets/image-preloads.liquid` — first-slide preload
- `assets/hero-banner.js` — standalone: no conditional activation, autoplay plugin at 5000ms, loop on, own dot block
- `assets/base.css` — hero card radius, decorative shape treatment, dot positioning

## Constraints

- Overwrites the existing themex `sections/hero-banner.liquid` — no settings carried forward
- Video beats image wherever both are set
- No CSS background images
- Arrows embedded in code
- Owns a complete standalone JS file using the Embla globals vendored by 0.6. Boots on `DOMContentLoaded`, not a Web Component — knowing exception to Global Standards §6.4
- Button radius as-designed per placement (F1); hover per the resolved F3 spec in 1.2
- Note: at hover the primary button becomes visually identical to the secondary's rest state, so the side-by-side hero CTAs will briefly read as two matching outline buttons. That is inherent to the inverse swap and is not a defect.

- [ ] White smile-underline variant renders on the hero heading
