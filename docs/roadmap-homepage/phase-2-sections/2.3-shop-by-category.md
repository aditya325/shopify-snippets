## Context

Sprint §4.6, "Recovery Starts Here". A grid of category cards with per-block background and
text colours, each card fully clickable, arrow rendered from the icon snippet.

The responsive behaviour is unusual and explicit: **desktop is a 5-column grid; mobile is two
rows — 3 columns then 2 columns.** The extraction confirms this — mobile shows a `Product Group`
of 3 cards at 112.67px each, then a `Daily Wellness Products` row of 2 cards at 174px each.
That is not a simple wrap; the two mobile rows have different column counts and card widths.

## Goal

A blocks-based category grid that renders 5-up on desktop and 3-then-2 on mobile, with fully
clickable cards carrying per-block colours and optional video.

## Requirements

### Functional
- Section-level richtext heading, underline-enabled
- Block type `category` with: image (`image_picker`), video (`video`), card title (text), background colour (`color`), text colour (`color`), link (`url`)
- **Video takes priority over image**; poster from `video.preview_image`
- Whole card clickable via the link; arrow from 1.1
- Desktop: 5-column grid. Mobile: first 3 blocks in a 3-column row, remaining in a 2-column row
- Measured padding: desktop 32 vertical / 60 sides, gap 24; mobile 24 vertical / 16 sides, gap 24

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- `presets` with five default blocks; no `max_blocks`

### Non-Functional
- Images as `<picture>` via `snippets/image.liquid`, lazy + `decoding="async"`
- Video muted, `playsinline`, looped, lazy-initialised near viewport

## Approach

The mobile 3-then-2 split is the whole difficulty. Rather than hardcoding "first three, then the
rest", decide and document the rule for block counts other than five — the design only shows
five. The defensible rule is: mobile lays out in rows of 3, with the final partial row expanding
to fill. That degrades sensibly at 4, 6 or 7 blocks and matches the design exactly at 5. Encode
it with a CSS grid that switches `grid-template-columns` at the breakpoint, using
`grid-auto-flow` and a nth-child rule for the trailing row rather than Liquid-side slicing —
Liquid slicing would break if a merchant reorders blocks.

Whole-card clickability uses the stretched-link pattern documented in the existing
`snippets/product-card.liquid`, so there are no nested anchors.

Per-block background and text colours come from block settings and must be applied as inline
custom properties on the card element, not as Tailwind classes — Tailwind cannot generate
classes for arbitrary merchant colours.

## Constraints

- Video beats image wherever both are set (Global Standards §7)
- No CSS background images; images are `<img>` with `object-fit`
- Merchant colours applied via inline custom properties, not generated Tailwind classes
- No nested anchors on the clickable card
- No `max_blocks`
