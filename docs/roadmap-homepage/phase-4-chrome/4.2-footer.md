## Context

Sprint §4.17. A full custom footer with newsletter capture and **four distinct block types**.
`sections/footer.liquid` and `config/footer-group.json` exist from themex but do not match this
contract — this is a rewrite.

Extraction: a `#113422` dark-green panel at radius 20, 1400px wide inside 20px page padding on
desktop (40px internal padding), dropping to 10px sides and 986.5px tall on mobile. Contains the
logo, about text, a 15%-off subscribe form, a 3-up trust carousel, three link columns, social
icons and a legal bar.

**Two layer-naming traps** recorded during extraction: the headline text node is named
`Link - +1 (973) 3333-5555` and the Subscribe button's label node is named `Shop Pore Care`.
Both render correct content; only the layer names are stale. Do not let them drive Liquid naming.

**Lato appears here** — the subscribe disclaimer is Lato Medium 12 desktop / 10 mobile, and it
is missing from Sprint §2.1's normalization table. It normalizes to DM Sans Medium 12 / 10.
0.4 adds the missing row.

## Goal

A custom footer matching the design, with four merchant-configurable block types and the shared
newsletter form, rendering correctly on every template.

## Requirements

### Functional
- Section-level: logo (`image_picker`, links to `/`), footer description (`richtext`), subscription label (`text`), footer heading (`richtext`), subline below field (`richtext`), copyright text (`richtext`), background colour (`color`), text colour (`color`)
- **Four block types**: USP (`image_picker` icon + `text` title), footer links (`link_list` — column heading derived from the menu title), social (`image_picker` SVG + `url`), policy (`text` label + `url`)
- Email capture renders `snippets/newsletter-form.liquid` from 1.4 with the footer style variant
- Logo links to the homepage
- Measured padding: desktop 20 sides / 20 bottom; mobile 10 sides / 10 bottom

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- `presets` populated with representative blocks of all four types; no `max_blocks`

### Non-Functional
- Below the fold on every page — all images lazy + `decoding="async"`
- Link columns are navigable by keyboard; social icons have accessible names
- The disclaimer renders DM Sans Medium 12 / 10, not Lato

## Approach

Rewrite `sections/footer.liquid` against the §4.17 contract and update `config/footer-group.json`
to match. Read the existing footer first to see what themex behaviour (if any) needs preserving.

Four block types in one section means a `{% case block.type %}` dispatch. Keep each branch small
and delegate rendering — social icons and USP icons both come through `image_picker` and
`snippets/image.liquid`, not from the 1.1 icon set, since they are merchant-supplied per Global
Standards §2.

Footer link column headings are **derived** from the `link_list` menu title, not authored — the
merchant picks a menu and the heading follows. Do not add a heading text field per column.

The newsletter form comes from 1.4. This is the second instance on the homepage (subscribe-letter
is the first), so it directly exercises 1.4's multi-instance requirement — verify both submit
independently on the rendered homepage.

Take the exact panel radius, internal padding, column widths and per-element type from the
"Footer" tables in `design-context.md`. The mobile layout restructures substantially rather than
simply stacking — read the mobile element tree, do not infer it from desktop.

This is site-wide: verify on collection, product, cart, search, blog and customer templates.
