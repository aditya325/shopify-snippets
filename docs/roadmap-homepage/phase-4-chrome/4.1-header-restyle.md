## Context

Sprint §1 places the header **out of scope as a build**: the themex boilerplate header is
restyled to match Figma, with the menu coming from Shopify navigation and **no schema
investment**. This PRD is therefore deliberately narrow — CSS and markup adjustment, not a new
section.

`sections/header.liquid`, `snippets/header-desktop.liquid`, `snippets/header-mobile.liquid`,
`assets/header-javascript.js` and `config/header-group.json` all already exist.

Extraction of the desktop header: 1440×110, white background, 60px side padding, logo 100×100
at radius 999 on the left, seven nav links at DM Sans Medium 16/24 `#171717` with 40px gaps
centred, and search + cart icons right. Mobile is 390×58 with 20px side padding — hamburger
left, 58px logo centre, search + cart right.

## Goal

The existing themex header visually matches the Figma design at both breakpoints, with menus
driven by Shopify navigation and no new schema fields.

## Requirements

### Functional

> **This section paints a background, so it takes BOTH:** `margin` on the wrapper for its separation from neighbours, and `padding` on the element carrying the background for the painted interior. Margin falls outside the painted box, so without the padding the band collapses to the content height (CLAUDE.md §5).
- Desktop: logo left, nav links centred, search and cart icons right — matching measured spacing and type
- Mobile: hamburger left, logo centre, search and cart right
- Menu items come from Shopify navigation (`linklists`), not hardcoded and not new schema
- Icons reuse the existing `icon-search`, `icon-cart`, `icon-hamburger` snippets, or 1.1 replacements where the audit found a mismatch
- Existing header behaviour is preserved: mobile menu toggle, search modal, cart drawer trigger
- **No new schema settings** — Sprint §1 is explicit

### Non-Functional
- Header is above the fold; the logo image is not lazy-loaded
- Nav is keyboard-navigable and the mobile menu toggle is focus-managed, as it is today

## Approach

This is a restyle, so start by reading `sections/header.liquid` and both header snippets to
understand what already exists before changing anything. The existing structure and JS stay;
only classes and minor markup adjust.

Resist scope creep. It will be tempting to add schema fields for spacing, colours or logo width
while in here — Sprint §1 rules that out. If a value genuinely needs to be merchant-controlled,
raise it as a change request rather than adding it silently.

`config/settings_schema.json` already has `logo` and `logo_width` settings; use those rather
than adding new ones.

Verify against every template, not just the homepage. The header renders on collection, product,
cart, search, blog, article and all customer templates. A spacing change that looks right on the
homepage can break the cart page's layout.

The Figma desktop layer being named `Mobile Menu` is a naming artefact only — build the 1440px
nav from it, and take the mobile header from `108:10688`.
