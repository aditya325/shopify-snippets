## Context

This is the final gate before sprint review. Every section was verified individually during
Phase 2, but individual verification misses the things that only appear on the assembled page:
inconsistent vertical rhythm between sections, tokens that drifted, the same component styled
two ways, and accessibility problems that span sections.

`@playwright/test` and `@axe-core/playwright` are in `devDependencies` but **no config or spec
exists anywhere in the repo** — the tooling was installed and never wired up. This PRD decides
whether to use it or verify manually.

## Goal

The built homepage is verified against the Figma design section by section at both viewports,
with accessibility and cross-browser checks complete and every remaining gap recorded in writing.

## Requirements

### Functional
- Compare built output against all 34 Figma screenshots — 17 sections × 2 viewports — using `sections.json` for canonical naming
- Verify the design tokens actually rendered: two font families only (no Poppins, Inter, Manrope, Lato or SF Pro in the built output), the §4 colour palette, measured per-section padding
- Verify one `<h1>` on the page and a sensible heading hierarchy below it
- Accessibility pass: keyboard navigation through every interactive element, focus visibility, carousel and tab ARIA semantics, alt text, colour contrast
- Cross-browser check at minimum Chrome, Safari and Firefox, plus iOS Safari at 390
- **Confirm the 3.1 and 3.2 gap reviews exist** if D2/D3 landed; record them as outstanding if not
- Record every unresolved item with an owner — nothing silently absorbed

### Non-Functional
- Findings are written down, not verbally reported

## Approach

Use the pipeline's `/compare` step, which reads `sections.json` directly and matches built
screenshots against the Figma set by canonical name. That is what the naming was set up for.

Decide the automation question early rather than drifting. Wiring Playwright + axe-core is
worthwhile if this theme will grow past the homepage — which it will, since Global Standards §1
anticipates further page sprints. If wiring it, keep scope to a single homepage spec with an axe
scan per section; do not build a test framework. If not wiring it, verify manually and record
the decision so the unused devDependencies can be removed.

**Do not flag the five hidden Figma layers as missing.** `Product Card` (108:11416),
`Ticker` (108:11488), `Reorder Section` (108:12064), `Section` (108:12616) and
`Sticky Add to Cart` (108:11045) are `visible: false` in Figma and excluded by explicit decision.
Likewise the `Toggle Button` and the iOS `Navigation Bar` status-bar mock are not themeable
elements.

Font verification is worth doing programmatically — inspect computed styles across the page and
assert only Space Grotesk and DM Sans appear. The normalization table has seven rows and it is
easy for one to be missed, particularly the Lato disclaimer in the footer.

Outstanding open items likely to still be live at this point: OD1 (wishlist inert) and D2/D3.
List them explicitly in the handoff rather than letting sprint review discover them.

Hover is in scope for this pass now that F3 is resolved. Check the swap on every button variant,
confirm nothing reflows on hover, and verify hover does not stick after a tap on iOS Safari —
that last one is the most common way a `@media (hover: hover)` guard gets missed.

## Expected Output

- An accessibility findings list with severity
- Fixes applied for in-scope defects
- A written list of every remaining open item with owner — OD1, and D2/D3 if unlanded
- Either a Playwright + axe spec, or a recorded decision not to wire it
