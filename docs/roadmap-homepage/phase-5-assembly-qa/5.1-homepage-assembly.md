# PRD: 5.1 — Homepage Assembly

**Phase:** Phase 5 — Assembly & QA
**Priority:** P0
**Depends on:** All of Phase 2, plus 4.1 header-restyle and 4.2 footer
**Estimated scope:** Medium (3-5 files)

## Design Reference

- **Desktop:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=108-11414
- **Mobile:** Same file — node-id=108-10684
- **Frames:** Both full-page frames — `Home - Desktop` (1440 × 7009.5) and `Home - Mobile` (390 × 6919.5)

## Context

`templates/index.json` still holds themex demo content: a `hero-banner` entry carrying the old
themex settings (`subheading`, `text_alignment`, `overlay_opacity`), a `featured_collection`, and
a `newsletter`. Since 2.8 overwrites `sections/hero-banner.liquid` with an incompatible schema,
the existing template entry would render with orphaned settings — so replacement is required, not
optional.

By the time this PRD runs, all thirteen Phase 2 sections plus the header and footer exist and
have been verified individually. Nothing here is new construction; it is composition and default
content.

## Goal

`templates/index.json` renders the complete homepage in the Figma order, with default content in
every section so the page is presentable immediately after theme install.

## Requirements

### Functional
- `templates/index.json` replaced with the full section order (see the Phase 5 overview for the canonical list)
- Every section has default settings and blocks populated so the page is not empty on a fresh install
- Section IDs are stable, readable and kebab-cased
- The two app-wrapper sections (3.1, 3.2) are included in the order even though their widgets may not render yet
- `config/header-group.json` and `config/footer-group.json` reference the restyled header and rewritten footer
- Any orphaned themex sections no longer used by any template are identified and listed for removal — **listed, not deleted** in this PRD
- Default images reference the assets in `.buildspace/artifacts/home-page/figmaAssets/` where a section needs one

### Non-Functional
- Page renders with no Liquid errors and no console errors
- Section order is identical between desktop and mobile — the Figma frames share it

## Approach

Write `index.json` by hand rather than by dragging sections in the theme editor and exporting;
hand-authoring gives readable IDs and lets defaults be set deliberately.

Default content matters more than it looks. A merchant installing this theme should see a
coherent page, not sixteen empty section shells. Populate headings, labels and block sets from
the Figma content, and wire images to uploaded assets. The 73 downloaded Figma assets in
`figmaAssets/` have **not** been uploaded to Shopify Files — if this PRD needs CDN-backed
defaults, run `upload-shopify-assets.js --feature home-page` first and use the resulting
`shopifyRef` values from `assets-manifest.json`.

Do not delete unused themex sections here. Identify them, list them in the PR, and let that be a
separate decision — `featured-collection.liquid` and `announcement-bar.liquid` in particular may
be used by other templates or planned for future pages.

Verify the assembled page against the two full-frame Figma screenshots for **order and rhythm**,
not pixel fidelity — per-section fidelity is 5.3's job.

## Expected Output

- `templates/index.json` — full replacement with all sections, order and default content
- `config/header-group.json`, `config/footer-group.json` — verified against 4.1 and 4.2
- A list of orphaned themex sections recorded in the PR for a later removal decision
- Optionally `assets-manifest.json` updated with Shopify CDN URLs if defaults need them

## Dependencies

### Upstream (must be done first)
- All of Phase 2 (2.1–2.13)
- 4.1 header-restyle, 4.2 footer
- 3.1, 3.2 — needed for the order; their widgets can be absent

## Constraints

- Section order matches the Figma frames and is identical across viewports
- No section is deleted in this PRD — orphans are listed only
- Nothing merchant-visible is hardcoded; defaults live in the template, not the Liquid
- The old themex `hero-banner` settings must not survive into the new template
