# PRD: 0.2 — Colour Tokens

**Phase:** Phase 0 — Foundation & Unblock
**Priority:** P0
**Depends on:** None — can start immediately (parallel with 0.1)
**Estimated scope:** Small (3 files)

## Context

`snippets/css-variables.liquid` currently emits 19 colour custom properties driven by
`config/settings_schema.json`, each as a **space-separated RGB triplet** produced by
`color_extract` (e.g. `--color-primary: 70 110 46;`). `tailwind.config.js` consumes them as
`rgb(var(--color-primary) / <alpha-value>)`, which is what makes `bg-primary/50` work. Global
Standards §4 defines the Amrutanjan palette in hex, and nine of its named tokens do not exist
in the theme at all.

## Goal

The full Global Standards §4 palette is available as Tailwind utilities (`bg-brand-yellow`,
`text-sale`, `border-green-secondary`, …), merchant-editable from theme settings, in the RGB
triplet format the existing Tailwind config requires.

## Requirements

### Functional
- Add these tokens, converting each hex value to an RGB triplet: `--color-brand-yellow` (#FACC15), `--color-green-secondary` (#2A7A50), `--color-green-dark` (#113422), `--color-cream` (#FEF9EA), `--color-cream-alt` (#FAF8F4), `--color-sale` (#D93807), `--color-rating` (#FF9C05)
- Reset the existing `color_primary` default to `#466E2E` and `color_accent` to `#F4C430`
- Map §4's `--color-text` / `--color-text-muted` onto the theme's existing `--color-foreground` / `--color-muted` rather than introducing duplicates; set defaults `#171717` and `#737373`
- Each token appears in all three files: `settings_schema.json`, `css-variables.liquid`, `tailwind.config.js`

### Non-Functional
- Existing themex tokens (`primary-light`, `primary-wash`, `body`, `mid`, `background-alt`, status colours) are left intact — nothing is removed

## Approach

Follow the established three-file lockstep. In `config/settings_schema.json` add one `color`
setting per new token in the existing colour group, using the hex defaults above. In
`snippets/css-variables.liquid` add a matching line using the same
`{{ settings.x | color_extract: 'red' }} {{ ... 'green' }} {{ ... 'blue' }}` pattern as its
neighbours — do **not** emit hex, or the `<alpha-value>` modifier breaks. In
`tailwind.config.js` add each to `theme.extend.colors` as
`'brand-yellow': 'rgb(var(--color-brand-yellow) / <alpha-value>)'`.

The three discount-banner colours (#00949E, #E6790F, #0094D1) are **not** tokens — Sprint §4.2
sets them per block via a `color_background` field, so they stay merchant-controlled at block
level. Do not add them here.

## Expected Output

- `config/settings_schema.json` — 7 new colour settings, 2 defaults updated
- `snippets/css-variables.liquid` — 7 new custom property lines
- `tailwind.config.js` — 7 new entries under `theme.extend.colors`
- `config/settings_data.json` — values populated so the palette is live without manual editor work

## Dependencies

### Upstream (must be done first)
- None

### Downstream (unblocked by this phase)
- 1.2 button-snippet — variants reference `bg-primary`, `bg-accent`, `border-green-secondary`
- 1.3 section-header-smile-underline — `--underline-color` defaults to the accent token
- All of Phase 2 — every section uses palette utilities

## Constraints

- CSS custom properties must be RGB triplets, not hex — this is dictated by the existing Tailwind config and is not negotiable without rewriting all 19 existing tokens
- Discount-banner colours are per-block merchant settings, not global tokens
- `assets/tailwind.css` is generated output

## Acceptance Criteria

- [ ] All 7 new tokens exist in `settings_schema.json`, `css-variables.liquid` and `tailwind.config.js`
- [ ] `--color-primary` resolves to `70 110 46` and `--color-accent` to `244 196 48` in rendered page source
- [ ] `bg-brand-yellow`, `text-sale`, `text-rating`, `bg-green-dark`, `border-green-secondary` and `bg-cream` all produce correct colours in a test render
- [ ] Alpha modifiers work — `bg-primary/50` renders at 50% opacity
- [ ] No existing themex token was removed or renamed
- [ ] Changing a colour in the theme editor updates the rendered page
