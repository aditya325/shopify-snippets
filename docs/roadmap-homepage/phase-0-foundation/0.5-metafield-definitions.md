# PRD: 0.5 — Metafield Definitions

**Phase:** Phase 0 — Foundation & Unblock
**Priority:** P0
**Depends on:** None — can start immediately (parallel with 0.1, 0.2, 0.4)
**Estimated scope:** Small (admin config + 1 documentation file)

## Context

Sprint §3 lists six metafield definitions that the product card and article card read from.
This is dependency **D1**, and it blocks 1.5 product-card and 1.6 article-card outright — those
snippets have no data source without it. The key names in §3 are explicitly labelled
*proposals*; final namespaces and keys are fixed when the definitions are created in admin.
Nothing in the card snippets may hardcode this data.

The store is `amrutanjan.myshopify.com` and `.env` holds `SHOPIFY_STORE` and
`SHOPIFY_ADMIN_TOKEN`.

## Goal

All six metafield definitions exist in the Shopify admin with final namespaces and keys
recorded, so the card snippets can be written against a fixed contract.

## Requirements

### Functional
- Create 5 product definitions: `product_badge` (single line text), `category_label` (single line text), `highlight_color` (color), `highlight_text` (single line text), `card_image` (file reference)
- Create 1 article definition: `read_time` (single line text or integer — pick one and record it)
- All definitions use a consistent namespace; `custom` is the §3 proposal
- Definitions are marked storefront-visible so Liquid can read them
- Final namespace/key pairs are written back into Sprint §3, replacing the proposals

### Non-Functional
- Populate at least two real products and one article with sample values so downstream PRDs have something to render against

## Approach

Create the definitions via the Shopify admin UI (Settings → Custom data) or the Admin GraphQL
`metafieldDefinitionCreate` mutation — the existing `SHOPIFY_ADMIN_TOKEN` may need the
`write_metafield_definitions` scope added to the dev app first; check before starting.

Two decisions must be made and recorded here rather than deferred:

**`read_time` type.** Integer is cleaner for sorting and validation but forces the theme to
append the unit string; single line text lets the merchant write "4 min read" verbatim. Pick
one, record it in Sprint §3, and the article-card PRD follows it.

**OD2 — radiator image source.** Sprint §4.5 leaves open whether the radiator background behind
the card image is a static theme asset or a product metafield. Decide it here. A static theme
asset is simpler and matches the design (the shape appears identical across cards); a metafield
adds per-product control nobody has asked for. Recommend static asset, record the decision, and
do not add a sixth product metafield unless the decision goes the other way.

Populate sample data on real products so 1.5 can be built and visually compared rather than
developed blind.

## Expected Output

- Six metafield definitions live in the Shopify admin
- `docs/tdds/amrutanjan-homepage-sprint.md` §3 updated with final namespaces and keys, `read_time` type fixed, and OD2 resolved
- Sample values populated on at least 2 products and 1 article

## Dependencies

### Upstream (must be done first)
- None

### Downstream (unblocked by this phase)
- 1.5 product-card — reads five of the six definitions
- 1.6 article-card — reads `read_time`
- 2.11 tabbed-product-collection, 2.12 featured-products, 2.13 featured-blogs

## Constraints

- All product-card data comes from metafields, never hardcoded (Sprint §3)
- One colour metafield (`highlight_color`) drives **both** the category badge text colour and the highlight text colour — do not create two
- Definitions must be storefront-visible or Liquid cannot read them
- Catalog assumption is single-variant products only

## Acceptance Criteria

- [ ] All 6 definitions exist in admin with the recorded namespace and keys
- [ ] Each definition is storefront-visible and readable from Liquid
- [ ] `read_time` type is decided and recorded in Sprint §3
- [ ] OD2 radiator image source is decided and recorded
- [ ] Sprint §3 no longer contains proposal placeholders
- [ ] At least 2 products and 1 article carry sample values
- [ ] A product with **no** metafield values set still returns blank rather than erroring when read
