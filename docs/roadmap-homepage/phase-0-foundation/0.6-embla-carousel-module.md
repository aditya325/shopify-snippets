# PRD: 0.6 — Embla Setup

**Phase:** Phase 0 — Foundation & Unblock
**Priority:** P0
**Depends on:** None — can start immediately (parallel with 0.1, 0.2, 0.4, 0.5)
**Estimated scope:** Small (3 files)

## Context

Dependency **D5**. Nothing carousel-related exists in `assets/` today.

This PRD is **Embla setup only** — vendor the library and load it. Each carousel section owns its
own standalone JS file, written in that section's own PRD. Nothing is shared beyond the library
itself.

Five sections will use it: 2.5 announcement-banner, 2.6 media-carousel, 2.7 featured-discounts,
2.8 hero-banner, 2.12 featured-products.

## Goal

Embla and its autoplay plugin vendored into `assets/` and loaded globally, so any section can use
the `EmblaCarousel` and `EmblaCarouselAutoplay` globals.

## Requirements

### Functional

- Download and commit both UMD builds into `assets/`:
  - `embla-carousel.umd.js` — v8.6.0, 17,946 B, exposes `EmblaCarousel`
  - `embla-carousel-autoplay.umd.js` — v8.6.0, 2,451 B, exposes `EmblaCarouselAutoplay`
- Load both from `snippets/core-assets.liquid`, deferred, core first then autoplay
- Runtime `src` is `{{ '…' | asset_url }}` — unpkg is the download source only, never the runtime origin
- Not added to `package.json`

### Non-Functional

- Deferred, not render-blocking. Deferred classic scripts preserve order, so no polling guard for the global is needed.

## Approach

```
https://unpkg.com/embla-carousel@8.6.0/embla-carousel.umd.js
https://unpkg.com/embla-carousel-autoplay@8.6.0/embla-carousel-autoplay.umd.js
```

Download both, commit to `assets/`, add two `<script … defer>` tags to
`snippets/core-assets.liquid` in that order.

The theme's shared-asset snippet is `core-assets.liquid` — there is no `core-libraries.liquid`
here.

## Expected Output

- `assets/embla-carousel.umd.js`
- `assets/embla-carousel-autoplay.umd.js`
- `snippets/core-assets.liquid` — two deferred script tags

## Dependencies

### Upstream (must be done first)
- None

### Downstream (unblocked by this phase)
- 2.5, 2.6, 2.7, 2.8, 2.12 — each writes its own carousel JS against these globals

## Constraints

- Vendored static assets only; no CDN at runtime (Global Standards §8)
- UMD globals, not ES modules
- Do not add Embla to `package.json`
- **Knowing exception to Global Standards §7** — the library loads globally (~20 KB) including on carousel-free pages. Section JS still loads per-section

## Acceptance Criteria

- [ ] Both UMD files are in `assets/` at v8.6.0
- [ ] Both load from `core-assets.liquid` via `asset_url`, deferred, core before autoplay
- [ ] No unpkg request at runtime; no npm runtime dependency
- [ ] `window.EmblaCarousel` and `window.EmblaCarouselAutoplay` are both defined on a rendered page
- [ ] No polling guard for the globals is needed anywhere
- [ ] Global Standards §7 exception is recorded in the TDD
