# PRD: 0.3 — Spacing Tokens

**Phase:** Phase 0 — Foundation & Unblock
**Priority:** P0
**Depends on:** 0.1 breakpoint-alignment
**Estimated scope:** Small (2-3 files)

## Context

Global Standards §5 defines a standard rhythm — desktop 60px side padding (1320px content on
1440), 32px vertical, 24px gap; mobile 20px side, 24px vertical, 20px gap — plus a documented
set of per-section exceptions that are followed as measured, not normalised. `assets/base.css`
already carries a `.page-width` utility from themex. After 0.1, breakpoint names match the TDD,
so responsive spacing utilities can be authored safely.

## Goal

A reusable section-wrapper pattern that delivers the standard rhythm by default and lets any
section override side padding, vertical spacing and gap without hand-writing arbitrary values
in thirteen places.

## Requirements

### Functional
- A `.page-width` (or equivalent) container yields 1320px max content with 60px side padding at desktop and 20px at mobile
- Standard vertical spacing (32 desktop / 24 mobile) and gap (24 desktop / 20 mobile) are expressible as utilities or a shared wrapper class. ⚠️ **Amended 2026-08-11 (from 2.2): vertical spacing is `margin` on the section wrapper, not padding** — see CLAUDE.md §5
- Documented exceptions from §5 are all reachable: 20px sides (hero, discount, footer), 72px sides (announcement banner), 10px sides (subscribe-letter, media-carousel, footer mobile), 16px sides (shop-by-category mobile), 8px sides (hero mobile, featured-discounts mobile), 44px bottom (featured-blogs mobile), and full-bleed (hero-text, timeline, featured-blogs wrapper)
- Every section can set its own padding via schema `margin_top` / `margin_bottom` range settings without fighting the wrapper

### Non-Functional
- The pattern must not introduce a wrapper div that breaks full-bleed sections

## Approach

Audit the existing `.page-width` rule in `assets/base.css` first and extend rather than replace
it — themex sections already depend on it. Express the standard rhythm as Tailwind utilities
composed in Liquid (`px-5 lg:px-[60px] py-6 lg:py-8 gap-5 lg:gap-6`) rather than inventing a
bespoke CSS class per section, so the values stay visible at the call site and Tailwind can
tree-shake.

Because §5's exceptions are numerous and deliberately un-normalised, do **not** try to encode
every exception as a named utility. Provide the standard wrapper plus a documented convention
for overriding, and let each section PRD apply its own measured values. Record the convention
in `assets/base.css` as a comment block so later phases follow it.

Full-bleed sections (hero-text, timeline, featured-blogs) must be able to opt out of the
container entirely — the wrapper is opt-in, not applied by a section group.

## Expected Output

- `assets/base.css` — extended `.page-width`, plus a documented spacing convention comment block
- `tailwind.config.js` — spacing scale additions only if a measured value has no existing Tailwind step
- A short convention note recorded in the phase overview or `CLAUDE.md` so Phase 2 PRDs apply it consistently

## Dependencies

### Upstream (must be done first)
- 0.1 breakpoint-alignment — utilities are breakpoint-scoped

### Downstream (unblocked by this phase)
- All of Phase 2 — every section applies the wrapper or an explicit exception
- 4.2 footer

## Constraints

- Per-section padding is followed **as measured in Figma**; normalising the scattered mobile side paddings is a designer decision, not a build decision (Global Standards §5.2)
- Non-utility CSS goes in `assets/base.css`, never `src/input.css`
- Do not remove or repurpose the existing `.page-width` — themex sections use it

## Acceptance Criteria

- [ ] Standard section renders 1320px content with 60px sides at ≥1440 and 20px sides at 390
- [ ] Standard vertical spacing measures 32px desktop / 24px mobile, applied as `margin`
- [ ] Standard internal gap measures 24px desktop / 20px mobile
- [ ] A full-bleed section can opt out of the container with no residual horizontal padding
- [ ] Each of the §5 exception values is achievable and documented
- [ ] Existing themex pages using `.page-width` are unchanged visually
