# PRD: 0.4 — Typography

**Phase:** Phase 0 — Foundation & Unblock
**Priority:** P0
**Depends on:** None — can start immediately (parallel with 0.1, 0.2)
**Estimated scope:** Medium (4-5 files)

## Context

`snippets/css-variables.liquid` loads fonts through Shopify's font picker
(`settings.type_primary_font | font_face`) and currently emits only regular + bold for each of
two families. Global Standards §3.1 and D4 originally mandated self-hosted WOFF2; that has been
**superseded** — Space Grotesk is confirmed available in Shopify's font library, so both
families come from `font_picker`. Global Standards needs a v1.3 bump recording this.

The unresolved risk is weight coverage. `font_modify` **returns `nil`** when a family lacks the
requested variant, and coverage differs per font. The design needs DM Sans at **400, 500, 600
and 700**, and Space Grotesk at **700** (plus 500/600 on non-heading text). If those weights are
absent from Shopify's library, this decision reverses back to self-hosting.

## Goal

Space Grotesk and DM Sans loaded via `font_picker` with every weight the design requires
verified present, above-the-fold weights preloaded, and the full type scale from Global
Standards §3.2–3.3 available as Tailwind utilities.

## Requirements

### Functional
- **Weight spike first.** Set both pickers, render `font_modify: 'weight', '400' | '500' | '600' | '700'` for each family, and assert none return `nil`. Record the result. If any required weight is missing, stop and escalate before continuing.
- `settings.type_primary_font` defaults to Space Grotesk; `type_secondary_font` defaults to DM Sans
- `css-variables.liquid` emits `@font_face` for every verified weight, with `font_display: 'swap'`
- Type scale tokens from §3.2 (mobile base) and §3.3 (desktop) available as Tailwind utilities: `hero-heading` 32/56, `section-heading` 24/34, `strip-heading` 26/38, `offer-display` 32/42, `subheading` 16/18, `body` 12/14
- Above-the-fold weights only are preloaded — the hero uses Space Grotesk 700 and DM Sans 400/600
- Every `font_modify` call uses a `| default:` fallback chain so a missing variant degrades rather than rendering nothing

### Non-Functional
- `font-display: swap` on all faces; no render-blocking font requests

## Approach

Do the spike as a throwaway Liquid render before touching config — it is a five-minute check
with a binary outcome that governs the rest of the PRD. Once weights are confirmed, extend the
existing `{% style %}` block in `css-variables.liquid` with one `font_face` line per weight,
following the pattern already there.

Add the type scale to `tailwind.config.js` under `theme.extend.fontSize`, each entry carrying
its line-height from the Figma extraction rather than a Tailwind default. Reference
`.buildspace/artifacts/home-page/design-context.md` for exact per-style line-height and
letter-spacing values — they are measured, not derived.

Preloading uses `snippets/image-preloads.liquid` as the precedent for where preload tags belong
in `layout/theme.liquid`. Preload only the weights the hero actually paints.

Update Global Standards §3.1 and D4 to v1.3 to record the picker decision, and add the missing
**Lato** row to Sprint §2.1's normalization table (footer subscribe disclaimer, Lato Medium
12 desktop / 10 mobile → DM Sans Medium 12 / 10).

## Expected Output

- `config/settings_schema.json` / `settings_data.json` — font picker defaults
- `snippets/css-variables.liquid` — `font_face` per verified weight, family custom properties
- `tailwind.config.js` — `fontSize` scale with measured line-heights
- `layout/theme.liquid` — preload tags for above-the-fold weights
- `docs/tdds/amrutanjan-global-standards.md` — v1.3 bump on §3.1 / D4
- `docs/tdds/amrutanjan-homepage-sprint.md` — Lato row added to §2.1

## Constraints

- `font_modify` returns `nil` for unavailable variants — always chain `| default:`
- Only two families ship; Poppins, Inter, Manrope and Lato all normalize to DM Sans, family swap only, size and weight preserved
- Space Grotesk "Medium" normalization applies to **headings only** — Space Grotesk 500 also appears on non-headings (blog card titles, category labels) which must not be bolded
