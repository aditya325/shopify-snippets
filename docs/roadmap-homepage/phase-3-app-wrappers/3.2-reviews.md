## Context

Sprint §4.15, "Real People. Real Relief." Rendered by Judge.me. This is dependency **D2**, which
has wider reach than this section alone: Judge.me also supplies the **rating preview badge inside
`snippets/product-card.liquid`** (1.5), which currently ships as a guarded no-op.

The theme provides the wrapper and header only. Widget typography should be aligned to DM Sans
"via widget CSS where the app allows" (Sprint §2.1) — Judge.me review author names are Manrope
SemiBold 13 in Figma and normalize to DM Sans SemiBold 13.

Extraction shows the intended design as three `Review` cards at 290px on mobile in a scrolling
row.

## Goal

A section wrapper with the standard header that mounts the Judge.me widget, with widget
typography aligned to the theme where the app permits, and the product-card rating row enabled
in the same pass.

## Requirements

### Functional

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). A `Measured padding:` figure states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- Section-level heading (`richtext`, underline-enabled) via 1.3
- An `app` block type for the Judge.me widget mount
- Section-level `margin_top` / `margin_bottom` matching the measured values
- `presets` so the section is addable in the theme editor
- Section renders its heading correctly with **no** app block present
- Widget typography overridden to DM Sans where Judge.me's CSS surface allows; where it does not, the gap is documented rather than forced
- **When D2 lands, enable the guarded rating row in 1.5 product-card** — this is part of this PRD's scope, not a separate ticket

### Non-Functional
- Judge.me scripts deferred; no render-blocking tags
- Widget CSS overrides must be scoped so they cannot leak into unrelated theme styles

## Approach

Same as 3.1 — build and verify the wrapper before D2 arrives, since heading, underline, padding
and preset are all testable standalone.

The typography alignment is best-effort by design. Judge.me exposes a limited CSS surface;
target only the selectors it documents as stable, and scope every override under the section
wrapper so a future widget markup change cannot cascade elsewhere. Where a style cannot be
reached, record it in the gap review rather than resorting to `!important` chains or DOM
rewriting.

The product-card rating row is the part most likely to be forgotten. 1.5 ships it as a guarded
no-op that emits nothing and reserves no space. When D2 lands, revisit
`snippets/product-card.liquid`, enable the badge, and re-verify that all five existing call
sites (collection, search, product-recommendations, recently-viewed-products,
featured-collection) still render correctly with the badge present — adding a rating row changes
card height on four pages beyond the homepage.

Then perform the gap review: screenshot the real widget at 390 and 1440 against
`screenshots/figma-reviews-{desktop,mobile}.png` and write up every difference before sprint
review.
