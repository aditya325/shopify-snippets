## Context

Sprint §4.14. Shoppable video, rendered by the Quinn app. This is dependency **D3** — Quinn is
not installed, so the widget's real output is unknown.

The theme's job is narrow: the section wrapper, the standard header with smile underline, the
measured padding, and the app block mount. Nothing inside the widget is the theme's
responsibility.

Extraction shows the intended design as four `Media Item` instances at 304px wide in a scrolling
row on mobile, and a wider arrangement on desktop, with 12 image assets already downloaded to
`figmaAssets/`.

## Goal

A section wrapper with the standard header that mounts the Quinn app block, styled and spaced to
match the design, ready for the app to render into.

## Requirements

### Functional

> **Vertical spacing is `margin` on the section wrapper, not padding** (CLAUDE.md §5). A `Measured padding:` figure states what Figma measures — Figma models all spacing as frame padding — and is a measurement, not an instruction to use the CSS `padding` property.
- Section-level heading (`richtext`, underline-enabled) via 1.3
- An `app` block type for the Quinn widget mount
- Section-level `margin_top` / `margin_bottom` matching the measured values
- `presets` so the section is addable in the theme editor
- The section renders its heading correctly **even when the app block is absent** — a merchant who has not added the widget sees the header, not a broken layout
- No content rendering of any kind belongs to the theme here

### Non-Functional
- The app block must not introduce render-blocking script tags
- Section is below the fold — nothing in the wrapper is eager-loaded

## Approach

Build and verify the wrapper **before** D3 lands. The wrapper is fully testable without Quinn:
the heading, underline, padding and preset all work standalone, and the `app` block simply has
nothing to render into it. Shipping the wrapper early means the only remaining work when Quinn
arrives is configuration and the gap review.

Declare the `app` block type in the schema per Shopify's app-block convention so Quinn's block
appears in the theme editor's block picker once installed. Do not hardcode a Quinn script tag or
embed code — app blocks are the supported mechanism and they handle their own loading.

Do not attempt to reproduce the Figma media row in the theme as a placeholder. Building a
lookalike that Quinn then replaces is wasted work and creates confusion about which is
authoritative.

Once D3 lands, perform the gap review: screenshot Quinn's actual output at 390 and 1440, compare
against `screenshots/figma-see-it-in-action-{desktop,mobile}.png`, and write up every visual
difference. Per Sprint §4.14 this happens **before sprint review** and is never silently
absorbed.
