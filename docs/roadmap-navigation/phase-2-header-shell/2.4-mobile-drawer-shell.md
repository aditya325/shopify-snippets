## Context

`snippets/header-mobile.liquid:82-177` ships a drawer today: left-anchored, `w-full max-w-sm`
(384px), one level deep, using `snippets/accordion.liquid`. Sprint §4.4 needs 360px over a 390px
viewport, two levels, and a back subheader. This PRD rewrites it to render from the same blocks 2.2
defined, so content is identical to desktop and only the rendering differs.

**F2 resolves to 52px — D-3 in `deviations.md`.** Sprint §2.2 gives `drawer-row` as 48px tall with
padding 14 and 20, which contradicts itself: measured row `389:28390` is `padding: 14px 20px` around
a 24px line-height label, so 14 + 24 + 14 = 52.

**The drawer uses two navigation metaphors and both are correct.** Root rows push to a sub-page with
a back control (`389:28613`); inside that sub-page the rail rows are an accordion whose expanded row
holds the pane content (`389:29994`). Build both.

> ⛔ **The TDD is frozen.** Never edit `docs/tdds/amrutanjan-navigation-sprint.md`.

## Goal

A 360px drawer that overlays the page, pushes to a second level with a back control, and renders
every panel's content from the 2.2 blocks as accordion rows.

## Requirements

### Functional
- Panel 360px wide over a 390px viewport, leaving a ~30px sliver of page visible; **overlays, never pushes**
- Drawer header 64px, `padding-inline: 20px`, `border-bottom: 1px #e5e5e5`, 40px circular logo left, 24px `x-circle` close right
- Root rows: `padding: 14px 20px`, label DM Sans Medium 16/24 `#171717`, `border-bottom: 1px #e5e5e5`, 18px chevron pointing down — **52px tall**
- Tapping a root row pushes to that panel's page; a subheader carries a back control and the level title in Space Grotesk Medium 18
- Inside a level-2 page, rail rows are an accordion; the expanded row reveals its pane content
- Utility strip pins to the base of the drawer — `padding 20`, `gap 16`, same green circle-icon links as desktop
- Back returns to the root without losing scroll position
- Offers and Track Order render as plain rows with no chevron and no push

### Non-Functional
- Focus is trapped inside the open drawer; body scroll is locked
- Closing returns focus to the hamburger

## Approach

Rewrite the drawer half of `header-mobile.liquid` and render the panes from `section.blocks` using
the same grouping helper 2.2 built, so nothing is duplicated. `snippets/accordion.liquid` is reusable
for the level-2 rail rows, but the level-1 → level-2 push is new and needs its own handling — a
translated track holding both levels, or swapping panels with a transform.

Prefer a CSS transform over animating `left`/`width`. The back transition is the forward transition
reversed.

The 360-over-390 sliver is the design's own affordance for closing — tapping the visible page edge
should close the drawer, as should the backdrop.

Body scroll lock must not cause the background to jump on iOS; use `overflow: hidden` plus a
compensating `padding-right` for the scrollbar, and restore the exact scroll position on close.

Extend `assets/header-javascript.js` rather than adding a file. Bind via `data-*`.

## Expected Output

- `snippets/header-mobile.liquid` — drawer rewritten to 360px, two levels, block-driven
- `assets/header-javascript.js` — push/back navigation, focus trap, scroll lock
- CSS for the drawer transitions

## Dependencies

### Downstream (unblocked by this phase)

## Constraints

- 360px fixed panel width — this is the design, not a max-width
- Overlay, never push (Sprint §4.4)
- Content is identical to desktop and driven by the same blocks — no mobile-only settings
- Drawer row is **52px**, correcting Sprint §2.2's 48 (D-3)
- `snippets/accordion.liquid` exists and should be reused for level-2 rows where it fits
