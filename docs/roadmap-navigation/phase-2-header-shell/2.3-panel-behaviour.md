## Context

2.2 has rendered every pane into the DOM and toggles them; this PRD makes them open, close and
switch. Sprint §4.1 and §4.2 own the behaviour. Nothing here fetches — §4.2 is explicit that the
whole menu is available without JavaScript requests, so this is presentation logic only.

**F3 is unresolved in the design.** Sprint §7 lists open/close duration and easing as TBD. The
approved resolution is a house default: **250ms `ease-out`**, matching the 150ms/`ease` hover
convention from `docs/roadmap-homepage/phase-1-shared-components/1.2-button-snippet.md` but scaled for a
larger moving element. Record it under *Still open* in `deviations.md` and flag for designer sign-off
at 4.3.

Measured panel heights vary widely — Categories 495px, Media 573px, Combo 605px, Shop By Need 637px,
About History 668px — which is exactly why §4.1 requires runtime measurement rather than a constant.

## Goal

Panels open and close on hover with an animated height, switch rail content instantly, and are fully
operable by keyboard and touch.

## Requirements

### Functional
- Opens on hover of a top-level item; closes on mouse-out of **both** the item and the panel
- Height animates 0 → natural height and back; no instant show/hide
- Height measured at runtime, so switching rail items resizes smoothly
- Hovering or focusing a rail row swaps the pane; the selected row takes `#faf9f6` and the green inset bar
- Click and focus equivalents for keyboard and touch users, since hover is unreachable for them
- `Escape` closes an open panel and returns focus to its trigger
- Only one panel open at a time
- `prefers-reduced-motion` falls back to an immediate change with no animation

### Non-Functional
- `aria-expanded` on the trigger tracks state; the panel is `aria-hidden` when closed
- No layout thrash — read all measurements before writing styles

## Approach

Extend `assets/header-javascript.js` rather than adding a file, following the DOMContentLoaded
pattern the theme already uses. Bind by `data-*` attributes only.

Animate `height` from `0` to the measured `scrollHeight`, then set `height: auto` on `transitionend`
so a pane that reflows later is not clipped. On close, read the current height back before
transitioning to 0, or the transition has no start value and snaps.

Rail switching must not animate through zero — measure the incoming pane and transition the panel
between the two heights directly, otherwise switching rails collapses and re-expands.

Touch needs care: on touch devices the first tap on a chevroned item should open the panel rather
than follow the link, and the second should navigate. Detect via `pointer: coarse`, not user-agent
sniffing.

Add a small close delay (~150ms) on mouse-out so a diagonal cursor path from the trigger to the panel
does not close it. Standard mega-menu behaviour; its absence reads as a bug.

## Constraints

- No fetching; panes are pre-rendered and toggled (Sprint §4.2)
- Height is measured at runtime, never hardcoded — five panels have five different heights
- DOM targeting via `data-*` attributes, never class names
- Vanilla JS only; no framework, no bundler

## Acceptance Criteria

- [ ] Hovering a chevroned item opens its panel with an animated height; mouse-out of both closes it
- [ ] A diagonal cursor path from trigger to panel does not close the panel
- [ ] Switching rail rows resizes the panel smoothly without collapsing to zero first
- [ ] Keyboard: `Tab` reaches every trigger, `Enter`/`Space` opens, `Escape` closes and restores focus
- [ ] Touch: first tap opens, second navigates, verified on a real coarse-pointer device
- [ ] `aria-expanded` tracks state on every trigger; closed panels are `aria-hidden`
- [ ] With `prefers-reduced-motion: reduce`, open and close are instant
- [ ] Only one panel is open at any time
- [ ] A pane whose content reflows after opening is not clipped
- [ ] F3's value is recorded in `deviations.md`; the TDD is unchanged
