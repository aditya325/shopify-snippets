## Context

This PRD owns the **data model** and the **chrome** every panel shares; 2.3 owns behaviour and Phase
3 fills the panes. It replaces the themex boilerplate `mega_menu` block at
`sections/header.liquid:32-83`, a two-image dropdown unrelated to this design.

**The block model deviates from Sprint §3.1 — this is D-1 in `deviations.md` and is approved.**
Shopify caps a section at [50 blocks](https://shopify.dev/docs/storefronts/themes/architecture/limits);
§3.1's ten block types across 23 rails computes to roughly 134. Two changes bring it to **~25**:
chips and trending links become `richtext` settings holding multiple `<a>` tags rather than
`link_group`/`link_item` blocks, and every one-picker-per-rail pane (`products`, `bundle_list`,
`articles`, `press`, `bundle_featured`) becomes a setting on `rail_item`. Only `rail_item` (×23) and
`content_card` (×2) remain as blocks.

> ⛔ **The TDD is frozen.** Never edit `docs/tdds/amrutanjan-navigation-sprint.md`. `deviations.md`
> is the amendment record and wins wherever the two disagree.

## Goal

A block schema that holds the whole menu inside one section, and the shared panel chrome — rail,
pane frame, utility strip — rendering from it.

## Requirements

### Functional
- Block type `rail_item`: `menu_handle`, `rail_label`, `rail_icon`, `pane_heading`, `cta_label`, `cta_link`, `show_subscribe_promo`, `chip_color`, plus the folded pane settings — `product_collection` + `products_count`, `bundle_collection` + `bundles_count` + `bundle_cta_label`, `featured_product` + `featured_heading` + `featured_cta_label`, `articles_blog` / `press_blog` + count + `read_label`, `group_a_heading` + `group_a_style` + `group_a_links`, `group_b_*`, `history_image` + `history_caption` + `history_year`
- Block type `content_card`: `card_image`, `card_title`, `card_description`, `card_link`
- Ordering rule from Sprint §3: a `content_card` with no preceding `rail_item` is **not rendered** and is reported in the theme editor
- Panel opens at y=116, full-bleed, white, container `padding-top: 32px`, rail `x:60` `width:220`, content column `x:312`
- Rail rows: `padding 16`, icon 18px at `gap 12`, label DM Sans Medium 16/22 `-0.18px` `#171717`, `border-bottom: 1px #e5e5e5`, active row `#faf9f6` + `box-shadow: inset 3px 0 0 0 #466e2e`
- Utility strip: 59px, `padding 16px 64px`, `border-top: 0.5px #a3a3a3`, two links at `gap 32`, each a 27px `#466e2e` circle with a 16px icon at `gap 8`, label DM Sans Medium 14/20 `#466e2e`
- CTA fallback: when `cta_link` is empty and the rail has a collection or blog, the CTA links to it

### Non-Functional
- No hardcoded panel content; every string is a setting or comes from the menu

## Approach

Render panes into the markup and toggle them — Sprint §4.2 is explicit that panes are not fetched.
Group blocks by walking `section.blocks` in order and starting a new pane at each `rail_item`, which
is the §3 ordering rule expressed directly in Liquid.

`group_a_style` / `group_b_style` are a `select` of `chips | links`. Richtext output cannot carry
Tailwind classes, so style it with arbitrary variants on the wrapper —
`[&_p]:contents [&_a]:rounded-full [&_a]:bg-[var(--chip-bg)] [&_a]:px-4 [&_a]:py-2` for chips,
underlined green for links. **`[&_p]:contents` is load-bearing**: richtext wraps each line in a
block-level `<p>`, and `display: contents` promotes the anchors to direct flex children so wrap and
gap work. Without it the chips stack vertically. `chip_color` applies to all chips in a pane —
per-chip settings are not needed, the design has one uniform fill.

Pane width is 1068px when `show_subscribe_promo` is off, and 684px with a 352px promo at `x:1028`
when on. Derive it from the layout — do not declare a static `w-[1068px]`.

The editor report for an orphaned `content_card` renders only when `request.design_mode` is true;
the live storefront ignores it silently.

## Constraints

- **50 blocks per section is a hard cap** — the model must stay near 25 with headroom
- Panes are rendered and toggled, never fetched (Sprint §4.2)
- `rail_icon` bypasses `snippets/image.liquid` — see 0.2
- No static widths on layout elements; derive from the container
- Richtext is sanitised by Shopify to `<p> <br> <strong> <b> <em> <i> <u> <span> <a>` — safe to render unescaped

## Acceptance Criteria

- [ ] Schema defines exactly two block types, `rail_item` and `content_card`
- [ ] A full menu build stays at ≤30 blocks, verified by count in the theme editor
- [ ] Panes group correctly by the ordering rule; a `content_card` before any `rail_item` is not rendered
- [ ] That orphan is reported visibly in the theme editor and **silently ignored** on the live storefront
- [ ] Rail active row shows `#faf9f6` with a 3px inset `#466e2e` bar; inactive rows carry the `#e5e5e5` divider
- [ ] An unset `rail_icon` leaves no gap and no broken glyph
- [ ] Utility strip measures 59px with `padding 16/64` and a `0.5px #a3a3a3` top border
- [ ] A richtext group with three links renders three chips on one wrapping row at `gap 12`
- [ ] `chip_color` changes every chip in that pane
- [ ] Pane width is 1068px with the promo off and 684px with it on, derived not declared
- [ ] An empty `cta_link` falls back to the rail's collection or blog URL
- [ ] The as-built schema is confirmed under D-1 in `deviations.md`; the TDD is unchanged
