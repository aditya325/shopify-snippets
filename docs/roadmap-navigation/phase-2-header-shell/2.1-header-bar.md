## Goal

The header bar matches the design at both viewports in both scroll states, renders top-level items
and chevrons from the Shopify menu, and exposes the hooks 2.2 and 2.4 need.

## Requirements

### A. Resting bar
- Desktop 110px, `padding-inline: 60px`, white, logo 100px circle with `border-radius: 999px` and `box-shadow: 0 1px 2px rgba(0,0,0,.08)`
- Desktop nav `gap: 40px`, labels **DM Sans Medium 18/27** `#171717`, chevron 18px at `gap: 8px`
- Desktop actions — search, account, cart — 30px icons at `gap: 40px`
- Mobile **66px**, `padding-inline: 20px`, `padding-bottom: 8px`, items bottom-aligned; hamburger left, 58px logo centred, search + cart right, all 24px icons, groups at `gap: 20px`
- A chevron renders **only** on items with children — Offers and Track Order are plain links
- Active item carries a 4px accent underline flush with the panel's top edge at y=116

### B. Sticky state
- At `scrollY === 0` the header is in normal flow with its resting background
- Once scrolled it becomes sticky and takes the scrolled background
- Mobile scrolled: `rgba(70,110,46,0.2)` with `backdrop-filter: blur(22px)`
- Desktop scrolled: the translucent green wash from `389:29163`, over page content
- Driven by a `scrolled_background_color` section setting (Sprint §3.3), defaulting to the measured value
- **Zero layout shift** when the state flips
- Chevrons render in the scrolled state

### Non-Functional
- No hardcoded menu labels — everything iterates `linklists[section.settings.header_menu].links`
- Scroll handling uses `IntersectionObserver` or a throttle; no unthrottled `scroll` listener
- The background transition respects `prefers-reduced-motion`

## Approach

Edit both snippets in place rather than rewriting — they already iterate the menu correctly and
already render the chevron. Change the type scale, icon sizes, logo treatment and the chevron's
conditional.

`sections/header.liquid:2` currently ships `sticky top-0 z-50` **unconditionally**, so today the
header is always stuck and always solid. Make it conditional. Prefer a zero-height sentinel before
the header plus `IntersectionObserver` over a scroll listener — that avoids per-frame work and gives
no-layout-shift for free. Write the state to a `data-*` attribute on the header root, never a class;
CSS keys off that attribute and the colour comes from a custom property emitted by the section and
consumed with `var()` on the same element, the pattern `sections/claims.liquid` established.

**The announcement bar interaction needs a decision.** Sprint §1 leaves it as a homepage section, so
on the homepage the header sticks over a section it does not own. Decide whether the sentinel sits
above or below it and record the choice in `status-log.md` — `389:29163` shows the announcement bar
scrolling away beneath a stuck header.

Add the Sprint §3.3 settings this PRD owns: `logo`, `store_locator_label`, `store_locator_link`,
`consultation_label`, `consultation_link`, `scrolled_background_color`.

Mark up each top-level item with a `data-*` attribute carrying the menu item's handle, matching what
`rail_item.menu_handle` will hold, so 2.2 and 2.3 can bind to it.
