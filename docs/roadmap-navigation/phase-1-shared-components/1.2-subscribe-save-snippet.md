**Phase:** Phase 1 — Shared Components
**Priority:** P0
**Depends on:** None — independent of Phase 0
**Estimated scope:** Medium (1 new snippet + 1 section refactor)

- **Extraction:** `.buildspace/artifacts/navigation/design-context.md`

## Context

Sprint §6 and dependency **D5** call for the Subscribe and Save markup to be extracted into a shared
snippet so both the homepage section and the mega menu render it.
`sections/subscribe-letter.liquid` (305 lines) shipped via
`docs/roadmap-homepage/phase-2-sections/2.9-subscribe-letter.md` and is the only current renderer.

**The two renders are different layouts, not one layout in two places** — this is **D-11** in
`deviations.md`. Sprint §1 says "the existing homepage section is not modified", which cannot hold
literally, since extraction rewrites the section's body. Read it as *schema and rendered output
unchanged*.

| | Homepage band | Menu card |
|---|---|---|
| Shape | wide 2-column band | 352px column, `radius 20`, `padding 24` |
| Logo | yes | **no** |
| Subtitle | "On your monthly essentials" | **none** |
| Benefits | 2 × 2 grid | 4 × 1 stack, `gap 18` |

> ⛔ **The TDD is frozen.** Never edit `docs/tdds/amrutanjan-navigation-sprint.md`.

## Goal

One snippet renders both layouts from a `layout` parameter, the homepage section renders
byte-identically to today, and the mega menu gains the promo with no duplicated markup.

## Requirements

### Functional
- New `snippets/subscribe-save.liquid` accepting `layout: 'band' | 'card'`
- `band` reproduces the homepage output exactly — logo, subtitle, 2×2 benefit grid
- `card` renders the menu variant — no logo, no subtitle, 4×1 stack, 352px column
- All copy (headline, benefit titles and subtitles, placeholder, button label) passed by the caller, never hardcoded
- `sections/subscribe-letter.liquid` refactored to render the snippet with `layout: 'band'`; its `{% schema %}` untouched

### Non-Functional
- The newsletter form keeps working in both layouts — reuse `snippets/newsletter-form.liquid` rather than re-implementing

## Approach

Measured `card` values from `389:23655`: radial gradient `#f4c430` → `#b3a42f` (21%) → `#92942f`
(32%) → `#72832f` (42%) → `#466e2e` (77%); headline Space Grotesk 600 `30/43` white, capitalize,
`-0.2px`; benefit tile 46px `radius 6` on `rgba(255,255,255,.06)` holding a 24px icon, row `gap 16`,
list `gap 18`; benefit title 16/24 white, subtitle 14/20 `rgba(255,255,255,.6)`; form `gap 10`,
input h40 `padding 16/13` `border 1px rgba(255,255,255,.36)` `radius 8`; button h40 `padding 14/22`
`radius 8` white with a `#466e2e` SemiBold 14/21 label at `-0.28px`.

Per Sprint §2.1 normalisation, the Manrope SemiBold 16 benefit titles ship as **DM Sans SemiBold
16** — family swap only, size preserved.

Structure the snippet as a shared content block with two wrapper branches, not two independent
markup trees, so a copy change lands in one place. The benefit rows are identical between layouts
apart from their container's flex direction and gap.

The homepage regression is the acceptance gate: capture the rendered section's DOM before the
refactor and diff after.

## Expected Output

- `snippets/subscribe-save.liquid` — new, both layouts
- `sections/subscribe-letter.liquid` — body replaced by a `{% render %}`, schema unchanged
- Any non-utility CSS in `assets/base.css` or a nav-scoped file, never `src/input.css`

## Dependencies

### Upstream

### Downstream (unblocked by this phase)

## Constraints

- Homepage rendered output must be byte-identical after the refactor
- Manrope normalises to DM Sans per Sprint §2.1; only two families ship
- The gradient is radial with five stops — a two-stop linear approximation is not acceptable
