# PRD: 1.1 — product-card: hide Add to Cart

**Phase:** Phase 1 — Shared Components
**Priority:** P0
**Depends on:** None — independent of Phase 0
**Estimated scope:** Small (1 snippet edit) — with a wide regression surface

## Design Reference

- **File:** https://www.figma.com/design/MpunnzguzvJ2SsXESNVVZ7/Development-For-INTENT?node-id=389-22801
- **Frames:** `shop-by-need` (389:22802) cards are 170×250; `categories` (389:23289) cards are 170×266 — neither has an Add to Cart
- **Extraction:** `.buildspace/artifacts/navigation/` — already complete

## Context

Sprint §6 says product-card is reused "with Add to Cart hidden through a prop rather than a new
variant." **That prop does not exist.** `snippets/product-card.liquid:261` renders
`{% render 'add-to-cart-button' %}` unconditionally, and the snippet's only parameters are
`show_featured_image`, `hide_price`, `lazy_load` and `card_class`. This is **D-8** in
`deviations.md`.

The card was built by `docs/roadmap-homepage/phase-1-shared-components/1.5-product-card.md` and has **7 live
call sites**, verified by grep: `collection.liquid`, `search.liquid`,
`product-recommendations.liquid`, `recently-viewed-products.liquid`, `featured-collection.liquid`,
`featured-products.liquid`, `tabbed-product-collection.liquid`. Every one keeps its Add to Cart
button. This PRD is mostly regression work, not feature work.

> ⛔ **The TDD is frozen.** Never edit `docs/tdds/amrutanjan-navigation-sprint.md`.

## Goal

`product-card` accepts a `hide_add_to_cart` parameter that removes the button and reclaims its
space, with every existing call site rendering byte-identically.

## Requirements

### Functional
- New boolean param `hide_add_to_cart`, defaulting to **false** so no existing call site changes
- When true, the button is not rendered at all — not hidden with CSS
- When true, no residual gap, margin or reserved height remains where the button was
- The card's stretched title link still covers the whole card, including the reclaimed area
- Card renders correctly at the design's fixed 170px desktop width (250px tall on Shop By Need, 266px on Categories) and 2-up on mobile

### Non-Functional
- All 7 existing call sites verified unchanged in a real browser at 390 and 1440

## Approach

Add the parameter to the `{% liquid %}` preamble following the existing `hide_price` pattern —
`if hide_add_to_cart == null / assign hide_add_to_cart = false / endif` — then wrap the render at
line 261 in an `unless`. No variant, no second snippet, no CSS `display:none`; Sprint §6 is explicit
that a prop is the mechanism.

The gap matters more than the button. The card root is a flex column with a gap utility, so removing
the child leaves the gap correct — but check whether the price row or the button carries an `mt-*`
that becomes a trailing margin. Reclaimed space must collapse, not persist.

Update the `{% doc %}` block with the new `@param` line, following the trimmed convention set when
the homepage button snippet was amended — a bare parameter list, no added prose.

Regression is the real deliverable. Render each of the 7 call sites before and after, and confirm the
DOM is identical where `hide_add_to_cart` is not passed.

## Expected Output

- `snippets/product-card.liquid` — one new param, one `unless` wrapper, one `@param` doc line
- No other file changed

## Dependencies

### Upstream
- None

### Downstream (unblocked by this phase)
- 3.1 product panels — Shop By Need (6 cards) and Categories (5 cards), both without Add to Cart

## Constraints

- Default **must** be false — 7 live call sites depend on the button
- A prop, not a variant, and not a CSS hide (Sprint §6)
- Do not change any other card behaviour; the blast radius is deliberately one line of logic
- `card_class` overrides from the caller are unprefixed and beat the snippet's `lg:` utilities at every width — see the snippet's own doc block
