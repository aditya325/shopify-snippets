## Approach

Build **one** pane snippet with the link groups optional, not two. Categories is Shop By Need with
the groups switched off and a different count.

`group_a_links` and `group_b_links` are richtext, so style via arbitrary variants on the wrapper —
merchant markup cannot carry classes:

```liquid
<div class="flex flex-wrap gap-3 [&_p]:contents [&_a]:rounded-full [&_a]:bg-[var(--chip-bg)] [&_a]:px-4 [&_a]:py-2">
  {{ block.settings.group_a_links }}
</div>
```

`[&_p]:contents` is load-bearing — richtext wraps each line in a block-level `<p>`, and
`display: contents` promotes the anchors to direct flex children so wrap and gap apply. Without it
the chips stack vertically. The fill comes from `chip_color` (2.2), defaulting to `#fde047`.

Per Sprint §2.1 normalisation the chip label's Inter Medium 14 ships as **DM Sans Medium 14**.

**Card width is fixed at 170px, and this is one of the few places the project's derive-don't-declare
rule does not apply.** Measured: cards sit at x = 0, 182, 364, 546, 728, 910 — a 170px card on a
182px pitch, so `gap 12`. Six of them end at **1080px inside a 1068px container**, a 12px overflow;
Categories' five end at 898px, leaving 170px of trailing space rather than distributing. So the row
is a **fixed-width card track**, not a grid dividing the container — which is consistent with the
mobile behaviour, where the row scrolls.

Do **not** implement this as `flex-1` across the pane. A derived width would compute
(1068 − 5×12) / 6 = **168px**, not 170, and would stretch Categories' five cards to 204px each —
neither matches the design. Build a fixed 170px basis with `gap 12` and let the track overflow or
scroll; confirm the intended overflow behaviour at 4.3, since a 12px clip in Figma may itself be a
design slip.

**Do not add icons to the Categories rail.** `rail_icon` stays optional in the schema and Categories
leaves it unset; 2.2's requirement that an unset icon leaves no gap is what makes this work.

The mobile Categories rail labels differ from desktop, and 0.1 has already picked one set. Follow
that decision; if 4.3 raises it, the entry in `deviations.md` is the answer.
